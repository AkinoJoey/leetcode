45分の進め方

解けるかどうかより、進め方で落ちる。手順を固定して、考える余力を問題に回す。

面接官が採点しているのは正解そのものではなく、正解に至る過程です。 無言で15分考えて正解を書く候補者より、喋りながら詰まって部分解に着地する候補者のほうが通ることがある。 以下は毎回同じ順でなぞるための台本。順番を暗記して、当日は考えない。

時間配分の目安

分やること沈黙してよいか
0–3① 問題の確認・具体例不可
3–5② 素朴解を口頭で（書かない）不可
5–10③ ボトルネック特定 → 方針決定短ければ可
10–30④ 実装可（ただし要所で実況）
30–40⑤ 手でトレース・エッジケース不可
40–45⑥ 計算量の総括・改善余地不可

① 問題の確認（0–3分）

  • 問題を自分の言葉で言い直す。「つまり、連続する部分配列のうち和が最大のものの長さ、ですね?」
  • 具体例を1つ自分で作り、期待する出力を言う。ここで解釈のズレが潰れる。
  • 制約を聞く。n の上限は必ず聞く——n ≤ 10³ なら O(n²) で通る、10⁵ なら O(n log n) 以下が必須、と方針が決まる。
  • 入力の性質を聞く：負の数は? 空配列は? 重複は? ソート済みか?

② 素朴解を口頭で（3–5分）

書かない。20秒で言うだけ。飛ばさないこと。

素朴には全ペアを試せます。O(n²) ですね。ただ内側のループは過去の要素を探しているだけなので、 辞書に置き換えれば O(n) に落ちるはずです。そちらで書きます。

この20秒で、問題の理解・計算量の把握・トレードオフの自覚が同時に伝わる。 費用対効果が最大の習慣。最適解が即座に見えている場合でも省略しない。 いきなり最適解を書く候補者は「暗記してきた」と見られることがある。

素朴解は遠回りではない

最適化とは「素朴解のどこが無駄か」を特定する作業。素朴解がなければ、最適化は思いつくかどうかの運になる。 素朴解があれば手順になる——「この内側ループは何をしている? 探索だ。ならば辞書」。

素朴解が「思いつかない」とき

素朴解は最適解と同じレイヤーのアイデアではなく、問題文をそのままコードに直したもの。 「全部試して、条件を満たすものから最良を選ぶ」という定型に問題文を流し込むだけで、機械的に出る。

したがって出てこないときは、創造性ではなく問題文の理解が足りていない—— パターンが先に発火して、精読を飛ばしている。対処は「ひねり出す」ではなく①に戻る。

パターン認識が速い人ほど要る

素朴解は定義上つねに正しい。だから当てはめたパターンが間違っていたときの検知器になる。 最適解と素朴解が小さい例で食い違ったら、間違っているのは最適解のほう。

例：Best Time to Buy and Sell Stock を「window」と誤認しても、 「全ての(買う日, 売る日)の組を試す」と一言でも口に出せば、 区間の問題ではなく2点を選ぶ問題だと即座に気づける。

時間の線引き：10秒で言えるなら言う。30秒で出ないなら精度を落として言って進む （「全探索なら指数時間だと思いますが、詰めずに最適解に行きます」で減点されない）。 素朴解の構築に2分使わない。目的は baseline の共有であって、素朴解の正確さではない。

③ ボトルネック特定（5–10分）

素朴解の内側がしていること置き換える道具
過去の要素の探索hash（Lesson 01）
連続区間の再計算sliding window（→）
ソート済み配列でのペア探索two pointers
毎回の最大／最小の取り出しheapq
同じ部分問題の再計算メモ化 / DP

方針が決まったら実装前に宣言する。「window で行きます。状態は set で、重複が出たら左を縮めます」。 ここで面接官が渋い顔をしたら、それは無料のヒント。素直に聞き返す。

④ 実装（10–30分）

  • 全部を実況しない（うるさい）。要所だけ——「ここで左を縮めます」「ここは窓が valid なので更新できます」。
  • 変数名は説明的に。i, j より left, right、d より seen。読み上げやすさが説明しやすさになる。
  • 詰まったら黙らない。「いま、縮める条件をどう書くかで迷っています」と言う。沈黙は情報がゼロだが、 これを言えば面接官はヒントを出せる。
  • 10分考えて最適解が見えないなら、素朴解を書いてしまう。 「まず O(n²) で通します。そのあと最適化します」。0点と部分点の差になる。

⑤ トレース・エッジケース（30–40分）

提出前に、必ず自分で具体例を1つ手で流す。「実行してみます」ではなく、変数の値を口に出して追う。 バグを面接官より先に自分で見つけると、評価はむしろ上がる。

毎回確認するリスト：

  • 空の入力 [] / ""
  • 要素1個
  • 全部同じ値／全部異なる値
  • 負の数、ゼロ（window が使えなくなる典型要因）
  • off-by-one：窓の長さは right - left + 1 か?
  • 答えが見つからない場合の返り値

⑥ 総括（40–45分）

聞かれなくても言う。

時間は O(n)、空間は O(k)（k は文字種）です。二重ループに見えますが left は戻らないので、 内側は全体で n 回しか回りません。空間をさらに削るなら配列で持つ手もありますが、可読性はこちらが上だと思います。

用語の定義は 用語集（「単調」「償却論法」など）。
