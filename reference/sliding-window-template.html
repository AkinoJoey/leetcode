Sliding Window テンプレート

連続する部分配列・部分文字列を扱う型。暗記ではなく、引いて使うために。

1. 見分ける

問題文の合図選ぶ型
「連続する（contiguous / substring / subarray）」＋最長・最短・個数Sliding Window
「ソート済み配列」から条件を満たすペアTwo Pointers（両端から）
順序が無関係。存在・個数・グループ化Hash（→ チートシート）
連続でない部分集合を選ぶDP / backtracking

決定打は「連続」の二文字。部分列が飛び飛びでよいなら window は使えない。 窓は縮めた瞬間に、捨てた要素を二度と拾わないため。

2. 可変長ウィンドウ（最長を求める）

もっとも頻出。「条件を満たす限り伸ばし、破れたら縮める」。

def longest(s):
    state = {}                  # 窓の中身を表す状態
    left = 0
    best = 0

    for right, ch in enumerate(s):
        # 1) 右端を窓に入れる
        add(state, ch)

        # 2) 条件が破れている間、左を縮める
        while is_invalid(state):
            remove(state, s[left])
            left += 1

        # 3) ここで窓は必ず valid。答えを更新
        best = max(best, right - left + 1)

    return best
不変条件

while を抜けた時点で窓は常に valid。この一行を口に出せると、 なぜ最後に max を取ってよいかが説明できる。窓の長さは right - left + 1（+1 を落とすのが定番のバグ）。

最短を求める場合

不等号の向きが逆になる。「valid になるまで伸ばし、valid な間縮めながら答えを更新」。

while is_valid(state):
    best = min(best, right - left + 1)   # 縮める前に更新
    remove(state, s[left])
    left += 1

3. 固定長ウィンドウ（長さ k）

total = sum(nums[:k])
best = total
for right in range(k, len(nums)):
    total += nums[right] - nums[right - k]   # 入れて、出す
    best = max(best, total)

5. 計算量

O(n)。二重ループに見えるが、left は減ることがなく、各要素は高々1回入って1回出るだけ （償却解析）。面接ではこの一文をそのまま言う——「内側の while は全体で n 回しか回りません」。 空間は状態の大きさ、文字種が定数なら O(1)。

6. 境界の検算（オフバイワン対策）

境界は推論で確かめない。小さい具体値を代入する。 「range は終端を含まないから +1 が要るはず」という頭の中の推論は外れる。5秒で代入したほうが速く、確実。

書いた式代入して確かめる判定
range(k) で初期窓k=2 → 0,1 → 2個✓
range(k+1) で初期窓k=2 → 0,1,2 → 3個✗
right - left + 1left=right=3 → 1✓ 長さ1
range(len(a)-1, -1, -1)len=3 → 2,1,0✓ 逆順で0に到達
range(len(a), 0, -1)len=3 → 3,2,1✗ 添字3で落ち、0を飛ばす

固定長窓の対応関係（k=2, nums=[1,2,3] で常に確認できる）:

初期窓  nums[0 .. k-1]        → range(k)
最初のスライドで入る右端      → right = k
出ていく左端                  → nums[right - k]
ループ                        → range(k, len(nums))

7. Python の地雷

  • del counter[c] を忘れると、値0のキーが残って len(counter) が狂う。 「種類数」を条件に使うなら、0になったキーは消すこと。
  • defaultdict(int) は参照しただけでキーが生える。 if d[c] == 0 と書いた瞬間 c が辞書に増える。判定は d.get(c, 0) か c in d。
  • 窓の長さは right - left + 1。off-by-one の定番。
  • best = max(best, ...) の代入を落とさない。max(...) は値を返すだけで、 受け取らなければ何も起きない。エラーも出ないので発見が遅れる。
  • 逆順走査は range(len(a) - 1, -1, -1)。range(len(a), 0, -1) は 初回で IndexError、かつ添字0に到達しない。
  • left をループのたびに 0 に戻さない。戻した時点で O(n²) になり、 window ではなく総当たりになる。left の単調性がこの型の全てである。
  • 負の数を含む配列では「和が k 以上の最短区間」に window は使えない（縮めても和が増えうる）。 window の前提は単調性。
