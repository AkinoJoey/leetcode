Two Pointers テンプレート

両端から挟み撃つ型。sliding window の兄弟。

1. 見分ける

問題文の合図選ぶ型
ソート済み配列から、条件を満たすペアTwo Pointers（両端から）
「連続する」部分配列の最長・最短Sliding Window
回文（前後から対称に見る）Two Pointers（両端から）
ソートされていない＋ペアHash（→ チートシート）

決定打は「ソート済み」または「対称性」。 ソートされていないのにペアを探すなら、まず Hash を疑う（Two Sum は Hash、Two Sum II は Two Pointers）。

2. 骨格

left, right = 0, len(arr) - 1

while left < right:
    if 条件を満たす:
        return ...
    elif 小さすぎる:
        left += 1        # 大きくしたい
    else:
        right -= 1       # 小さくしたい
境界

while left < right（<= ではない）。ペアを探すので同じ要素を2回使わない。
回文判定など「中央の1文字は見なくてよい」場合も < でよい。 迷ったら代入検算 → 境界チェックリスト。

3. 「どちらを動かすか」の導き方 ← この型の本体

骨格は毎回同じ。問題ごとに違うのは動かす方向の決め方と、 捨てた候補を二度と見なくてよい理由だけ。ここも3段で出す。

  1. いま持っている値を書く（和、面積、距離など）
  2. どちらを動かすと目的の方向に動くかを、ソート順から言う
  3. 捨てる側に、より良い答えが残っていないことを一文で言う ← 面接で聞かれるのはここ
問題①いまの値②動かす基準③捨ててよい理由
167. Two Sum II arr[left] + arr[right] 和が小さすぎる → left += 1 arr[left] は残りで最大の相手と組んでも届かない。他はもっと小さい
125. Valid Palindrome 両端の文字 一致したら両方内側へ 対称性より、外側の対は二度と関係しない
11. Container With Most Water min(h[l], h[r]) × (r - l) 低いほうを内側へ 低い柱を残しても幅が減るだけ。面積は絶対に増えない
③を書く手順（いきなり文を書かない）

③の主語は、消えた組。②の主語はポインタ。ここがずれると、5回書いても②になる （実際に起きた → Lesson 12）。 文を書く前に、先に2つ名指しする：

  1. いま消えたのは、どの組か。添字で、1組ではなく集合で。 評価済みの組は含めない（もう答えに反映されている）
    例（4Sum, d -= 1）： (c+1,d) … (d-1,d) ＝ d を右端に持つ未評価の組すべて
  2. その全部が、手元の値と比べてどうなるか。根拠はソート順 / min / 添字のいずれか

この2つが埋まれば、③は「よって、それらは【目標】に達しない」で閉じるだけ。
1 が書けないうちに③を書こうとすると必ず②になる——手元に移動の話しか材料が無いから。

判定：「小さくできる」「動かせる」が入っていたら②。 ③に出てよいのは〈消えた組〉〈順序の根拠〉〈超えていた／届かなかったという事実〉の3つだけ。

③の3原則
  1. 値を知るのではなく、上限を押さえる。捨てる要素が他の相手と組んだ結果は 計算しない。「どんな相手でもこれを超えない」と言えれば足りる。
  2. 比較の基準は、すでに計算した値。③の主張は「捨てた中に良いものがない」ではなく、 より弱い「捨てたものは手元の値を超えられない」。計算済みのペアは捨てていない。
  3. 一般形で書く。「h[0] は…」ではなく「低いほうの柱は…」。 具体例で書くとどちらを捨てるかという適用条件が文面から消え、コードの分岐に落ちない。

上限はどこから来るか ＝ ソートが要るかの判定

問題何を押さえるか上限の出どころソート
167他の相手との和ソート順（arr[j] ≤ arr[right]）必須（問題文が保証）
15 / 16 / 18他の相手との和ソート順必須（自分で書く）
11面積min と添字 （水位 min(h[l],h[j]) ≤ h[l]、幅 j-l < r-l）不要
125外側の対の判定対称性不要

判定はこの一文に尽きる。
③が「値の大小」に依存しているならソートが要る。添字や対称性で済むなら要らない。

両方向を覚えること（片方だけだと必ず事故る）

要らない側：ソートは③の必須条件ではなく、上限を得る手段のひとつ。 11 では h[j] の値を最後まで一度も使わずに③が完成する ——ソートされていなくても捨てられる。→ Lesson 08
要る側：③の文に「〜より大きい／小さい」が現れたら、その順序は誰かが保証していなければならない。 問題文が保証していなければ nums.sort() を自分で書く。 16 はこの1行の欠落だけで 35% の入力に対して誤答した。→ Lesson 10

③を一般形で書けば、前提は文の中から自分で出てくる。 「ソート順より nums[k'] ≤ nums[k] なので和はさらに小さくなり…」—— この「ソート順より」が ⓪ に書くべき前提そのもの。

また、同じ sort() でも問題ごとに理由が違う。 15 のソートは③（単調性）と重複スキップの両方に効くが、16 は和を1つ返すだけなので 重複スキップは不要。15 の理由を 16 に持ち込まない。

③を言えないまま実装すると、正しくても「なぜ動くか説明できない解」になる。 面接官が最も踏み込むのがここ。プロトコルの③で口に出す。
さらに実務上：③が一般形で書ければ、コードの if の分岐条件はそこから自動的に決まる。 11 で「低いほうを捨てる」が③から落ちると、コードも left += 1 無条件になる（実際に起きた）。

4. 計算量

O(n)。償却論法（Lesson 04）は使わなくてよい。 この型には、もっと短くて反論の余地がない数え方がある——ギャップ論法。 

right - left は毎反復ちょうど1減る
（left += 1 か right -= 1 の一方が必ず起きるから）

開始 n-1 → 終了 0  ⇒  反復は高々 n-1 回

[時間1] n 回   [時間2] O(1)（加算と比較）   [時間3] -（内側ループなし）
⚠ log n と書かない

「捨てる」という語は二分探索と結びついているが、計算量を決めるのは捨てる理由ではなく捨てる量。

1回で捨てる候補反復回数
端の1本（Two Pointers）n
残りの半分（二分探索）log n

log n が出てよいのは、捨てる量が「残りの一定割合」のときだけ。 → Lesson 08

空間は追加の状態を持たなければ O(1)。ソートが必要なら O(n log n) が支配的になる。

4.5 入れ子（外側ループ ＋ two pointers）← 15. 3Sum の型

15 は新しい型ではなく、167 を n 回解く帰着。i を固定すれば 「ソート済み配列から和が -nums[i] のペアを探す」＝ 167 そのもの。 この形になった瞬間、足し算（償却）は使えなくなる。

内側のポインタは外側の反復に持ち越されるか数え方例
持ち越される（単調に進むだけ、戻らない） 足し算（償却）
[時間1] + [時間3]		 424, 3（sliding window）
リセットされる（j,k = i+1, n-1） 掛け算
[時間1] × [時間3]		 15, 16, 18
 
for i in range(len(nums)):          # n 回
    j, k = i + 1, len(nums) - 1     # ← ここでリセットされる＝償却できない
    while j < k:                    # 各 i で最大 n 回
        ...
→ n × O(n) = O(n²)（ソートの n log n は飲まれる）
内側ループの止め方は、外側の問題文が決める

167 は「解は1つ、見つけたら return」。15 は全部列挙なので、和が 0 でも break してはいけない（j += 1; k -= 1 で続行）。
内側は「その i に対する部分問題」を解ききる。 取りこぼしは必ず「同じ i の2組目以降」に出るので、テストは [-3,-1,0,1,2,3] のように同じ最小値で2組できる入力を使う。 

# 15 の重複スキップ（set を使わない標準形）
nums.sort()
for i in range(len(nums) - 2):
    if i > 0 and nums[i] == nums[i-1]:
        continue                       # 同じ i を二度やらない
    j, k = i + 1, len(nums) - 1
    while j < k:
        s = nums[i] + nums[j] + nums[k]
        if s < 0:   j += 1
        elif s > 0: k -= 1
        else:
            ans.append([nums[i], nums[j], nums[k]])
            j += 1
            while j < k and nums[j] == nums[j-1]:
                j += 1                 # j を進めた「あと」に置く
重複スキップの境界は、そのループの開始位置

if i > 0 の 0 に意味はない。i の開始位置がたまたま 0 だから。 段が増えたら、比べる相手も変わる： 

for a in range(...):            # a は 0 から
    if a > 0    and nums[a] == nums[a-1]: continue
    for b in range(a+1, ...):   # b は a+1 から
        if b > a+1 and nums[b] == nums[b-1]: continue

b > 1 と書くと、b がそのループの1周目（b == a+1）でも nums[b] == nums[a] なら飛ばしてしまう。[1,1,1,1] のような 同じ値が並ぶ解が丸ごと消える（18 で実際に起きた。ランダム4000件中 358件で誤答、 ただしLeetCode の例題は通る）。
意味は「このループで2周目以降なら、前回と同じ値を飛ばす」。だから比べる相手は常に開始位置。

スキップするのは左ポインタ側だけでよい（j / c）。 外側が固定されていれば、1つの左の値に対して和が一致する右の値は高々1つなので、 右側の重複は自動的に潰れる。

理由：i と j の値が決まれば、nums[k] = target - nums[i] - nums[j] は 値として一意に決まる。三つ組は3つの値で決まるのだから、2つが決まれば3つ目は自由度ゼロ。 よって (i, j) の値の組が重複しなければ、三つ組も重複しない。 右側を弾く仕事は残っていない。

break してよい条件（15 で1回、18 で1回まちがえた）

break は「このループの残り全部が不要」と証明できるときだけ。 1件の事実からは break できない。

言えていること可否
if nums[i] > 0: break ソート順より、以降の i' はすべて nums[i'] > 0。 3つとも正なので和は絶対に 0 にならない ＝ 残り全部について言えている 可
一致したので break（15 の初回） いま1組見つかった、それだけ。残りについて何も言えていない （167 は「1つ返せ」なので可、15 は「全部返せ」なので不可） 不可

内側ループの止め方は、外側の問題文が決める（→ Lesson 09）。 同じ break でも、根拠が「順序」なら可、「1件の発見」なら不可。

5. Python の地雷

  • while left < right を <= にすると、同じ要素を2回使ったペアを返す。
  • 1-indexed の問題がある。167 は答えを [left+1, right+1] で返す。問題文を読むこと。
  • 重複をスキップする問題（15. 3Sum）では while left < right and arr[left] == arr[left-1]: left += 1 の境界に注意。
  • 「ソート済み」と書いていないのに two pointers を使うなら、自分でソートした計算量を計上する。
