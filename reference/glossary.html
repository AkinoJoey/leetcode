知らない語が出てきたら、遠慮なく聞いてください。用語で詰まるのは、あなたの理解不足ではなく私の説明不足です。 聞かれた語はここに追加していきます。

計算量まわり

計算量 / O 記法

入力の大きさ n が増えたとき、処理時間がどういう伸び方をするかを表す記号。 定数倍と細かい項は捨てて、伸び方の形だけを見る。O(n²) は「n が10倍になると時間は100倍」、 O(n) は「10倍」、O(log n) は「ほとんど増えない」。

記法意味典型
O(1)入力によらず一定辞書の参照
O(log n)半分ずつ絞る二分探索
O(n)1回なめるsliding window
O(n log n)ソートを含むsorted()
O(n²)総当たり（二重ループ）素朴な Two Sum

単調（monotonic）

一方向にしか動かず、逆戻りしないこと。 値が減る一方なら「単調減少」、増える一方なら「単調増加」（途中で止まるのは含む）。

重要なのは、単調だと分かった瞬間に動く回数に上限が付くこと。 left が 0〜n を戻らずに進むなら、動く回数は多くても n 回。これが償却論法の前提になる。

例：株価問題の min_price（7 → 1 → 1 → 1、下がるか同じ）、 sliding window の left（進むか止まるか、戻らない）。

償却論法（amortized analysis）

「最悪の1回」を回数分だけ掛けるのではなく、「全体の合計」で数える計算量の数え方。

二重ループに見えても、内側が回れる総回数に上限があるなら、掛け算ではなく足し算になる。

for right in ...:      # n 回
    while ...:         # ここは全体で合計 n 回しか回らない
        left += 1      # left は単調 → 0〜n しか動けない

素朴に n × n = O(n²) と数えるのは数えすぎ。 重い反復は起こりうるが、それが n 回連続では起こりえないため。合計 n + n = O(n) が正しい。

日常の例：年12回の家賃を「最も高くつく日 × 365日」と数えないのと同じ。実際に発生する合計を見る。

面接での言い方（3文テンプレート）

① 二重ループに見えますが、left も right も戻りません。

② そのため各要素は、入るときと出るときの最大2回しか触られません。

③ 全体で最大 2n 回の操作なので、時間は O(n) です。

「1回」ではなく「2回」。入るのが1回、出るのが1回。ここを1回と言うと理解の浅さを疑われる。

two pointers、sliding window、単調スタックでそのまま使い回せる。 詳細は Lesson 04。

データ構造まわり

ハッシュ可能（hashable）

辞書のキーや集合の要素にできるという性質。中身が変わらないもの（イミュータブル）だけが該当する。

可：int str tuple frozenset ／ 不可：list dict set Counter

詰まったら tuple() や frozenset() に変換する。 詳細は Python ハッシュ構造チートシート。

オフバイワン（off-by-one）

範囲や個数の指定が、正解より1だけ多い／少ない誤り。

「0 から数えるか 1 から数えるか」「終端を含むか含まないか」が食い違うときに起きる。 対処は推論ではなく代入検算 → 境界の検算チェックリスト。

不変条件（invariant）

コードの特定の地点で、必ず成り立っていると言い切れる条件。

例：sliding window で while を抜けた直後、窓は必ず valid。 だからそこで答えを更新してよい。不変条件を口に出せると、コードの正しさをコードなしで説明できる。

subarray と subsequence の違いは頻出の罠。「連続」なら窓、「飛び飛び可」なら窓は使えない （窓は縮めた時点で捨てた要素を二度と拾えないため）。

型の名前

sliding window（尺取り法）

配列上の連続区間 [left, right] を、右端を伸ばし・左端を縮めながら1回だけ走査する型。 → テンプレート

two pointers

2つの添字を配列の両端から中央へ寄せる型。ソート済み配列のペア探索が典型。 sliding window と兄弟だが、両端から寄る点が違う。

total order の話ではない語の注意

「最適解」＝計算量が理論下限に達した解。「素朴解 / brute force」＝思いつく総当たり。 面接では素朴解を先に口に出してから最適化するのが定石（黙って最適解を書くより高く評価される）。
