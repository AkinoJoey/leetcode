境界の検算チェックリスト

推論しない。小さい値を代入して数える。

手順（3秒）

  1. nums = [1, 2, 3], k = 2 を置く
  2. 先に手で答えを書き出す
  3. コードに代入して一致を見る

順序が重要。コードを先に見ると、脳はそれを正当化する方向に働く。

個数の公式

ほしいもの式検算（n=3, k=2）
添字 left 〜 right（両端含む）の要素数right - left + 10〜2 → 3個
長さ n の配列に入る長さ k の窓の数n - k + 12個
右端 right の窓の左端right - k + 1right=2 → left=1
右端 right のとき出ていく要素right - kright=2 → 添字0

+1 が要るのは両端の両方を含むとき。引き算だけだと「隙間の数」になり端が1つ落ちる。

range の境界

書き方生成される値個数
range(n)0, 1, …, n-1n 個
range(a, b)a, …, b-1b - a 個
range(len(nums)-1, -1, -1)n-1, …, 1, 0n 個（正しい逆順）
range(len(nums), 0, -1)n, …, 1誤り。初回で IndexError、0 に届かない

k 個ほしいなら range(k)。range(k+1) は1個多い。

固定長窓は変数を1本にする

window_sum = sum(nums[:k])
best = window_sum
for right in range(k, len(nums)):
    window_sum += nums[right]       # 入る
    window_sum -= nums[right - k]   # 出る（left ではない）
    best = max(best, window_sum)

left を別に持つと「引くべきは left か、その1つ前か」というねじれが生まれる。 right 1本で書けばずれる余地が減る。

提出前チェック

  • 要素1個（len(nums) == 1）で落ちないか
  • k == len(nums) のとき、ループが0回でも答えが出るか
  • ループの初回と最終回の添字を、実際に紙に書いたか
