# 説明の回収は成功／格子は成分を取り違えた／日が空くと細部が消える

Lesson 13（説明だけ、コードなし。題材 15. 3Sum）。
[[0018-loop-start-not-constant]] で残した3つの弱点を回収しにいった。

## 回収できた（検証点 a・b とも1回で通過）

**(a) `sort()` の時間計上**（2回連続欠落 → 通過）

> 「ソートで O(n log n)、二重ループで O(n²)。**O(n log n) は吸収されるため** O(n²)」

要点は結論ではなく「**吸収される**」と口に出したこと。
介入は **⑥は関数の1行目から上から順に読む。ループを探しに行かない。**
コスト台帳（行 × 1回あたり × 回数 × 小計）を表にして、`nums.sort()` の行を目立たせた。
**「抽象的な基準は、目で見えるものに変換する」の4勝目**（インデント→⑥／格子→③／台帳→前処理）。

**(b) ②のボトルネック**（2回連続欠落 → 通過）

> 「3重目が全てを舐めてしまうのがボトルネック」

介入は**形式チェック：素朴解に出てくる語がそのまま入っているか**。
入っていなければ最適解の説明になっている。
[[0016-indentation-decides]] と同じ処方（意味の判定を、文面の観察に落とす）。

空間も2往復目で回収（「ソートが必要なため O(n) の確保」）。

## ③：格子は使えたが、成分が入れ替わった

初回の答え：`(j+1..k, k)` の組が消える。
正しくは `(j, k')`（`k' = j+1..k-1`）。**第1成分と第2成分が逆。**

`j` を動かしたのに**列**（第2成分固定）が消えると書いた。
[[0017-subject-of-the-claim]] の格子は「`d -= 1` は列／`c += 1` は行」まで含めて教えたが、
**問題ごとに変数名が変わると対応が落ちる**（18 は `c,d`、15 は `j,k`）。
1往復で修正。**格子そのものは生きている。落ちたのは対応表のほう。**

### 「`k` は配列内で最大」

修正版に残った誤り。正しくは「**いま残っている範囲 `j..k` の中で最大**」。
初期状態（`k = n-1`）ではたまたま配列最大なので、**初期状態の付随的特徴が概念に貼り付いた**。
NOTES 既出の「例の付随的特徴が概念に貼り付く」の4例目。今回貼り付いたのは**例ではなく初期値**。
③の論理そのものは正しく閉じていたので、指摘のみ。

## 新しい観測：日が空くと細部が消える（storage strength）

追い質問2つが**両方とも空**になった。

- 「15 で最初に書いた `break` は何が違ったか」→ **「これも忘れちゃった」**
- 「なぜ左側の重複だけで足りるのか」→ **「わからない」**

後者は `two-pointers-template.html` に**答えが書いてある**（外側固定なら、1つの左の値に対し
和が一致する右は高々1つ）。**資料にあるのに引き出せない** ＝ fluency はあるが storage がない状態。

これまでの失敗はすべて「その場で言えない」型だったが、
**今回初めて「一度できたことが、間を空けたら消えた」型**が観測された。
15 は 2026-07-23、18 は 07-25、今回は 07-26。3日で消えている。

→ **以後、レッスン冒頭に「前々回の問題からの retrieval」を1問置く。**
直前の回ではなく**2回以上前**から引く（spacing）。

## 教えた内容（回収できなかった2問の答え）

**`break` の条件：このループの残り<em>全部</em>が不要と証明できるときだけ。**

| | 言えていること | 可否 |
|---|---|---|
| `if nums[i] > 0: break` | ソート順より以降の `i'` も全部正 ＝ **残り全部について**言えている | 可 |
| 一致したので `break`（15 の初回） | 1組見つかっただけ。残りについて何も言えていない | 不可 |

**左側の重複スキップだけで足りる理由：`i` と `j` の値が決まれば
`nums[k] = target - nums[i] - nums[j]` は値として一意に決まる。**
三つ組は3つの値で決まるのだから、2つ決まれば3つ目は自由度ゼロ。
`(i, j)` の値の組が重複しなければ三つ組も重複しない。**右側を弾く仕事は残っていない。**

どちらも `two-pointers-template.html` に追記（`break` は表つきで新設）。

## Implications

- two pointers は**説明側も含めて完了**。次の型（binary search）へ進んでよい。
  binary search は [[0011-discard-rate-vs-discard-reason]] の伏線回収でもある
  ——「捨てる → log n」がここで初めて正当化される。
- **新しい弱点は storage strength に移った。**これまでの弱点（言い忘れ、欄の取り違え）は
  その場の手続きで潰せたが、これは**時間をまたぐ設計**でしか潰せない。
  レッスン構造を変える：冒頭に retrieval 1問（2回以上前の問題から）。
- **正直な「忘れた／わからない」は歓迎すべき信号。**取り繕われると decay が見えない。
  `⚠` の「議論していない行」条件は、日が空くと機能しない（何を議論したか自体を忘れる）
  ——条件は「**このセッションで**」ではなく「**まだ一度も壊れたことのない行**」に変えるべきかもしれない（要検討）。
