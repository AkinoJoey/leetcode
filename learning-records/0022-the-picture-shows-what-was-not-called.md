# 図に描いた ✗ を根拠にした——述語ベースでは、呼んだ1点以外は未知

278. First Bad Version（型Bの2問目）。⓪★②③の4項目 → 実装まで通り、**完答**。
ランダム20万件（`n ≤ 200`、bad位置ランダム）＋ `n=1,2,3` の全境界で不一致0件。
**呼び出し回数の実測は最大8回**（`log₂200 ≈ 7.6`）＝⑥の主張と実測が一致。
704 の `l += 1` 事件（[[0020-the-rate-must-be-in-the-code]]）の再発なし。

## 詰まり：③で「まだ呼んでいない情報」を根拠にした

介入として ✗/✓ の真偽列を描いた（35 で効いた図の転用、[[0021-define-the-target-before-the-discard]] の検証点）。

```
version    1    2    3    4    5    6
isBad      ✗    ✗    ✗    ✓    ✓    ✓
                          ↑ mid = 4 で ✓
```

補助質問2つ（「答えは4より右にありうるか」「4自身はまだ候補か」）には**両方とも正答**。
にもかかわらず結論は「**図でいうと 1,2,3 が ✗ になっているから、やっぱり `1..mid-1` が消えている**」。

- **自分の答え1（右にありえない＝5,6が消える）と結論（左が消える）が同一メッセージ内で矛盾。**
- 原因は図そのもの。**私が描いた図には正解が全部描いてあった。**
  `isBadVersion(4)` を呼んだ時点でプログラムが知っているのは 4 が ✓ ということだけで、
  1,2,3 は一度も呼んでいない。**学習者は図から未評価の値を読み取って根拠にした。**

### 35 との違い＝図の「認識論的地位」が変わっていた

| | 35（配列あり） | 278（述語） |
|---|---|---|
| 図の ✗✓ | 配列の値から**誰でも見える** | `isBadVersion` を**呼ばないと見えない** |
| 図を根拠にしてよいか | よい | **呼んだ1点以外は不可** |

**図は転用できた。落ちたのは「見えている情報の範囲」のほう。**
[[0019-the-range-not-the-array]] で「格子は生きていて、落ちたのは変数名の対応表」と記録したのと同型
——**道具は生き延び、道具と問題の接続部が落ちる**。これで2例目。

## 介入：図を「判明している行」に描き替えた

```
version    1    2    3    4    5    6
真の姿      ✗    ✗    ✗    ✓    ✓    ✓     ← 説明用。プログラムには見えない
判明        ?    ?    ?    ✓    ?    ?     ← mid=4 を呼んだ直後
```

この2行を並べた直後に1往復で通過。
「**抽象的な基準は、目で見えるものに変換する**」の**7勝目**だが、今回は変換ではなく
**同じ図を2段（真の姿／判明）に分けた**。図を出す側の反省点：
**説明用の図が、そのまま根拠として使える図だとは限らない。**
→ 以後、述語ベース・オンライン系の問題で図を出すときは**最初から `?` 付きで描く。**

## 通過した項目

- **⓪ 通過。**配列が無いのに単調性を自分の言葉で書けた（「bad 以降の全てのバージョンで true」）。保証者も正答（問題文）。
  - 混入：「n を isBadVersion に入れて半分ずつ判定していく」＝**方針が⓪に入った**。軽く指摘。
    前提が成り立たない問題でも方針は書けてしまうので、欄は分けたい。
- **★ 探索対象の定義：一発で一文に畳めた**（`isBadVersion(i)` が true となる最小の `i`）。
  [[0021-define-the-target-before-the-discard]] で新設した欄が、**導入直後の1問で機能**。
  35 の3往復の主因（定義が2つに見えていた）は今回消えている。
- **② 通過。**ボトルネック文に素朴解の語（「舐めてしまう」）。形式チェック**4回連続**。
- **⑥ 両方の枝を名指し**（`l = mid+1, r = mid`）。
  [[0021-define-the-target-before-the-discard]] で残した観察項目を**1回で回収**。
  見えにくい側（`r = mid`）が自発的に出た。照合ルールは**4回連続作動＝獲得済みとみなす。**
- **⚠ `l = mid+1`。**条件変更（今日いちばん迷った行）後**2回連続で妥当**。
  迷いの正体は「なぜ片方だけ `+1` か」＝型Bの本質。急所。

## 教えた内容：±1 は左右では決まらない

> **その枝で `mid` が候補として生き残るかで決まる。**
> 答えではないと確定 → `mid ± 1`／答えかもしれない → `mid`（±1 なし）

「左は +1、右は無し」と**位置で覚えると型が変わった瞬間に崩れる**。
そして**③で「mid はまだ候補」と書いたなら、コードは `r = mid` になる**——③とコードは直結している。
`binary-search-template.html` の §4 に、この表と `first_true(lo, hi, pred)` の汎用形、
および上記の「?付きの図」を追記。

## storage strength：3セッションぶりに retrieval が空でなかった

冒頭 retrieval を記述式2問で実施（前回は課題提出から入って未実施）。

| 問 | 結果 |
|---|---|
| 11 の③（動かさなかった側の組の上限） | **半分**。「高さの上限が低い側で決まる」は出た。**幅が落ちた** |
| 704 の「半分を実現している行」 | **正答。しかも両方の枝**（`l = mid+1` / `r = mid-1`） |

- 11 の③は3セッション連続で空だったが、**今回初めて部分的に残っていた。**
  残ったのは高さ（＝上限の議論、[[0012-bound-not-value]] の中心）、消えたのは幅。
  面積の否定文は〈上限が据え置き〉×〈幅が必ず減る〉の**2要素**で閉じるので、片方では不十分。
  → **11 は完全回収まで retrieval に残す。**
- **私の Q1 の問題文が誤っていた**（消えるのは「動かさなかった柱を含む組」ではなく「動かした低い柱を含む組」）。
  学習者は問題文の誤りに引きずられず正しい対象を見ていた。
  → **retrieval の設問は、出す前に自分で解く。**

## Implications

- **型Bは 35・278 の2問通過。次は型C（回転配列 33 / 153）へ移ってよい。**
  型Cは「ソート済みですらない配列で、なお半分捨てられる」＝
  [[0014-...]] 以来強調してきた「⓪の前提」が**部分的にしか成り立たない**初のケース。
  ⓪の書き方そのものが試される。
- **獲得済みとみなす項目が3つに増えた**：⓪前提の名指し／②の形式チェック／⑥の照合ルール。
  いずれも「4回連続で作動」を基準にした。**retrieval の対象を、まだ獲得していない項目に絞れる。**
- 残る弱点は2つに絞られた：**③（毎回どこかで詰まる。5問連続）** と **storage（11 の幅）**。
  ③は詰まり方が毎回違う（主語／枝／未評価情報）ので、単一の手続きでは潰せていない。
  ただし**5問とも図で1往復以内に反転している**ので、介入自体は安定している。
