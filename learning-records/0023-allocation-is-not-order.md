# 配分は順序ではない——ROI表で計画を引き直した（DP 20h → 4h）

2026-07-30。レッスンではなく**計画の改訂**の記録。
学習者が日系メガベンチャー向けの「トピック × 習得コスト × ROI」対照表を持ち込み、
「ロードマップを引き直すべきか」と問うた。**答えは yes、ただし順序ではなく配分。**

## v1 の欠陥：時間配分を決めていなかった

v1（`reference/study-plan.html`、07-19 作成）は [NeetCode Roadmap](https://neetcode.io/roadmap) の
依存順をそのまま週割りにしたもので、**各トピックに何時間かけるかを明示的に決めていなかった。**
結果、DP に週8・週9の2週（約20時間）が積まれていた。

ROI表では DP は**習得コスト「高」・ROI ★1**——8トピック中で最悪の組み合わせ。
配列と文字列（★5）が v1 では週1の1週しかなかった。**★5が1週、★1が2週。**

| | v1 | v2 |
|---|---|---|
| 動的計画法（★1・高コスト） | 約20h（1-D + 2-D） | **約4h（1-D の3問のみ）** |
| 再帰／バックトラック（★3・高コスト） | 第6週 | **8月前半に前倒し** |
| 配列と文字列（★5・中コスト） | 週1のみ | **常設枠＋9/14週の再投資ブロック** |
| グラフ（★2・高コスト） | 1週（Union-Find含む） | 1週（**grid BFS/DFS ＋ 207 のみ**） |
| 二分探索（★2・高コスト） | 1週 | **支払い済み → 3問で打ち止め** |

**順序は1つも変えていない。**依存関係（再帰→木→グラフ／DP）が決めているので動かせない。
再帰の前倒しは順序の変更ではなく「高コストなものを早く始める」という配分の話。

## 判断の中核：ROI表とは何を測っているのか

ROI表は「**頻度 ÷ 習得コスト**」を測っている。だが学習者が最適化すべきは
「**あと何時間で、どれだけ伸びるか**」＝**限界ROI**。この2つは現在地によってずれる。

- 配列と文字列は★5だが、この学習者は Lesson 01〜09 で**最も進んだ**領域。
  → ★5枠の中身を「新パターンの追加」ではなく **2〜3問目の横展開と口頭練習の素材**に変えた。
- 二分探索は★2・高コストだが、Lesson 14〜16 で**コストは支払い済み**。
  ここで止めるのが正しく、型D以降には進まない。
- **★2のトピックで★5の道具が手に入っていた**：⓪前提の名指し／②素朴解とボトルネック／⑥量と行の照合。
  [[0022-the-picture-shows-what-was-not-called]] で「獲得済み」と判定した3項目は全トピックで使い回せる。
  **投資の回収先はトピック知識ではなく手続きだった。**

## 学習者が持ち込んだ2つの資料は、層が違う

同じセッション中に約140問の「良問リスト」（カテゴリ・難易度・重要度つき）が追加で提示された。
これは表面上 ROI表と矛盾する——**DPが最大セクション（約25問）で、ほぼ全て重要度「高」**。
2-D DP（Edit Distance / LCS / Unique Paths）やナップサックまで「高」。
私が削った部分がそのまま「高」で並んでいた。

読み方は2つあり、片方だけが成立する：

- ✗ **「全部やるリスト」**：約140問 × 40〜50分 ＝ **100時間超**。残り予算の全部で復習ゼロ。不可能。
- ✓ **「カテゴリ内の優先度リスト」**：重要度「高」は*そのカテゴリを勉強するなら*これを、という**カテゴリ内**の順位。

したがって **ROI表＝時間の配分 ／ 問題リスト＝配分内での問題選択**。層が違うので競合しない。
**これは今後も再利用する読み方**：外部の「重要度」表記は、ほぼ常にカテゴリ内相対であって、
カテゴリ間の時間配分を語っていない。

### リストを見て v2 を2箇所だけ修正した

- **207 Course Schedule を拾った**。★2＝低コストで、実体は「DFS で閉路検出」＝木の再帰の延長。
  切るべきは **743（Dijkstra）と 684（Union-Find）**——新しいアルゴリズムを1つずつ要求する方。
  「グラフを切る」ではなく「**新規のデータ構造を要求する問題を切る**」が正しい切り口だった。
- **DP の床を★2の問題で組んだ**（70 / 746 / 198）。当初案の 322 Coin Change は★3で、床には高すぎる。
- Aizu Online Judge のナップサック3問は**不採用**（MISSION の out of scope＝競技プログラミング）。

## 成果物

- `reference/study-plan.html` を **v2 に全面改訂**（変更点・ROI表・読み方の注意3点・切り方の順序）
- `reference/problem-set.html` を**新設**：140問 → **56問**に選抜、週ごとに割り当て、

- `RESOURCES.md` に持ち込み資料2点を追加（**出典未確認**であることを明記）

## 明示した賭けと、その反証条件

DP を約25問 → **3問**に削ったのは意図的な賭け。外れる条件を先に書いた：

> **志望先の選考が実質DP勝負だった場合。**選考情報や過去問でその兆候が出たら即座に配分を組み替える。

同様に、ROI表そのものも**出典未確認**でありFAANG系の頻度データ（木・グラフが実質2番目に重い）と食い違う。
学習者に確認して**志望先＝日系メガベンチャー中心**と確定したので採用したが、
**志望先が変われば表の妥当性も変わる**。`RESOURCES.md` の Gaps に記録済み。

## 配分で動かなかったもの

**口頭説明が未経験であるというリスクは、どう配分しても1ミリも減らない。**
模擬面接（8月下旬に初回・9月下旬に2〜3回）は v1 のまま維持し、再配分の対象外とした。
8/24週は問題数を7問→**5問に減らして**模擬面接に寄せた。

回収した約15時間の使い道を学習者に選ばせたところ、**「配列と文字列の問題数」を選択**（模擬面接の増回は選ばれなかった）。
v1 の模擬面接の回数は維持されるので許容したが、**初回模擬面接の直後が次の計画見直し点**であることを両文書に明記した。
そこで初めて口頭説明の実力が測れる——**測ってから残り5週の配分を決める。**

## Implications

- **次の行動は変わらない**：Lesson 16 の課題（33 / 153）→ 875 Koko で二分探索を締める。
  計画改訂は「この先9週の中身」を変えたが、今日の課題は変えていない。
- 8/03週から**新パターン2つ**（prefix sum・スタック）に入る。v1 でスキップされていた箇所。
  ③の詰まりが5問連続で続いているので、**新パターン導入時の③の出方を観察する**。
- **計画文書は「不採用の理由」まで書かないと機能しない。**v1 は削る順序を書いていたが、
  何を削ったかの記録がなかった（そもそも選抜していなかった）。
