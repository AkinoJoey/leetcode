# rubric 化で、説明の質が3往復で基準に到達した

[[0008-explanation-lags-implementation]] を受けて⑥を自由記述から枠付き（rubric）に変更した結果、
424 の②⑥が3往復で全項目クリアした。

**Evidence（往復ごとの変化）:**

| 回 | 空間 | 時間 | 素朴解 |
|---|---|---|---|
| 1（自由記述） | `O(min(1,26))` 誤 | 根拠のみ、O(26) 言及なし | 問題文の言い換え、max_freq なし |
| 2（rubric 初回） | **3段すべて正確** | [時間2] に償却の 2n を誤って投入 | 「全部試す」が欠落 |
| 3 | 同上 | **全項目正確**（[時間3]=n も正しい） | **max_freq を含む正しい素朴解** |

**Implications:**
- **枠を用意すると、その枠は埋まる。**空間は rubric 初回で一発正解。前回 `O(min(1,26))` と誤った同じ人物が、
  導出3段（状態 → 最大要素数 → 入力依存か）を与えられただけで正しく書いた。
  問題は知識ではなく**想起の足場**がなかったこと。以後、定着させたい手続きは必ず提出物に枠として埋め込む。
- 一方 **枠の粒度が誤っていると混同を誘発する**。[時間2]（毎回必ず走るコスト）に
  償却の 2n を入れたのは本人のミスではなく、424 には性質の違う「内側」が2つある
  （毎回走る `max()` と、回るとは限らない `while`）のに枠を1つしか用意しなかった設計ミス。
  → [時間2]/[時間3] に分割。**LR-0007（`is_invalid` を隠していた）と同じ、抽象化の粒度の失敗。3回目。**
- 分割後、[時間3] を `2n` ではなく `n` と正しく書いた。while だけを数える枠だと理解した上での回答で、
  枠の意図が伝わったことの証拠。**償却論法（Lesson 04）は定着したとみなす。**
- 語彙の問題も判明：「素朴解＝問題文の**直訳**」という私の説明が「言い換え」と解釈されていた。
  → **「何を全部試すかを必ず含める」**に変更。抽象語で指示すると解釈が割れる。

**残った弱点:**
- ボトルネックの言語化が最も弱い。「部分文字列ごとに数えること」で基準は満たしたが、
  「**重なった部分を数え直している**」（＝ window の売り文句そのもの）までは自力で出なかった。
  誘導質問を2つ出しても届かなかったので、今回は与えた。次に window 型を解くとき再確認する。
