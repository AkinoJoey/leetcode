# 18 完答。計算量の根拠を初めて回収／重複スキップの境界を定数で書いた／`⚠` が摩耗した

18. 4Sum を完答。two pointers は 167・11・125・15・16・18 の6問通過。
新形式（実装前／実装後の自由記述、枠は採点側）の初の完走。

## 最大の成果：⑥の根拠が出た（LR-0016 の検証点）

> 「二重ループを作り、**その中でポインタを毎回初期化して**ループしているため O(n³)」

[[0016-indentation-decides]] で導入した判定法（**初期化行が外側ループの外か中か**）が、
結論ではなく**根拠として**出た。**同じ場所で3回連続外していた項目を1回で回収。**
しかも 18 は判定法を2回適用する構造で、それを1文で処理している。

**「抽象的な基準は、目で見えるものに変換する」が、これで3勝目**
（インデント → ⑥／ペア空間の格子 → ③／…）。この workspace の第一選択の介入として確立したとみなす。

## バグ：`b > 1`（重複スキップの境界を定数で書いた）

```
[0,1,1,1,1], t=4          提出 []             正解 [(1,1,1,1)]
[-2,-1,-1,1,1,2,2], t=0   提出 1組            正解 2組
ランダム4000件: 358件失敗 (9%) / b > a+1 で 0件
LeetCode の例題 [1,0,-1,0,-2,2] は通る       ← 手元テストでは気づけない
```

```python
if a > 0   and nums[a] == nums[a-1]: continue   # a は 0 から始まる
if b > 1   and nums[b] == nums[b-1]: continue   # b は a+1 から始まる ← 誤り
```

**規則：重複スキップの境界は、そのループの開始位置。定数ではない。**
`a > 0` の `0` に意味はなく、`a` の開始位置がたまたま 0 なだけ。
意味は「このループで**2周目以降**なら、前回と同じ値を飛ばす」。

`b > 1` だと `b` がそのループの1周目（`b == a+1`）でも飛ばすため、
**同じ値が4つ並ぶ解が丸ごと消える。**

### これは「持ち込み」の5例目、コードでは2例目

`a > 0` の**形**を4行下の `b` にそのまま持ってきた。
[[0014-inner-loop-multiplies]] の `break`（167 → 15）と同型だが、
今回は前問ではなく**同じ関数内の4行上から**。
**「前問の文面を持ち込む癖」は、距離とは無関係に「形の流用」として起きる。**
→ `two-pointers-template.html` に「重複スキップの境界は開始位置」を追加（kSum 一般で使える形で）。

## `⚠` が摩耗した（7回連続で途切れ）

挙げたのは `if b > a+1 and nums[b] == nums[b-1]`——**たった今直したばかりの行**。
壊れていたと分かっている行を挙げるのは予測ではなく**回想**。
この欄の価値は「**まだ検証されていない場所を当てる**」ことにある。

NOTES に「167 で解決済みの `left < right` を3回連続で挙げた＝摩耗」と記録済みで、
**同じ摩耗が「直後に修正した行を挙げる」という新しい形で再発**した。
→ 以後、`⚠` は明示的に「**このセッションでまだ議論していない行**」と条件を付けて聞く。

未議論の真の候補：`while c < d and nums[c] == nums[c-1]`
（**なぜ左側の重複だけスキップすれば足りるのか**＝外側固定なら1つの左の値に対し和が一致する右は高々1つ）。
追い質問として投げ、回答は次セッションに持ち越し。

## `sort()` を空間には計上するが、時間には計上しない（2回連続）

16 でも 18 でも、空間 `O(n)` の根拠に `sort` を挙げられるのに、
時間で `O(n log n)` が吸収される点に触れない。
[[0014-inner-loop-multiplies]] の「自分で書いた操作が⑥に現れない」の**部分的な残存**——
空間側だけ修復されて時間側が残っている。名前を付けて次回冒頭で一度だけ確認する。

## 実装前パートの評価

- **⓪前提は満点**（条件＋保証しているのが問題文かコードか）。獲得済み。
- **③は Lesson 12 の格子で1往復で通過**（詳細 [[0017-subject-of-the-claim]]）。
- **② のボトルネックは2回連続で欠落**（素朴解 `O(n⁴)` は正答）。次の要観察項目。
- 方針の `while a < d`（外側を two pointers にしようとした）は、
  **自分の素朴解 `O(n⁴)` との突き合わせで露見**。検算が機能する形になっている。
- 範囲の上限 `range(len(nums)-2)`（正しくは `-3`）は**正しさに影響しない**ので軽く触れるに留めた。

## Implications

- two pointers は6問通過。**型としては獲得済み。**残る弱点は説明側に3つ：
  ②のボトルネック（2回連続欠落）／`sort()` の時間計上（2回連続欠落）／`⚠` の摩耗。
  **いずれもアルゴリズムではなく「言い忘れ」の型**——ミッション（面接で声に出す）では致命的なので、
  次の型（binary search か monotonic stack）に移る前に1問だけ既習問題で回収する。
- 新形式は初の完走。**枠の撤去による劣化は2問とも観測されず**、むしろ空間欄の自己矛盾は消えた。
