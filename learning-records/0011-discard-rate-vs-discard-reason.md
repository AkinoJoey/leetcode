# 「捨てる」の理由は言えたが、量を数えていない（O(log n) 誤答）

167 は自力完答。骨格・境界・1-indexed すべて正しい。`⚠` に挙げた `left < right` も、
このコードで唯一議論の余地がある行（`<=` にすると同一要素のペアを返す）＝**照準は正確**。
[[0008-explanation-lags-implementation]] 以降、`⚠` 欄は3回連続で機能している。

**⑥ の誤り: `[時間1] 外側は何回回るか: logn回` → 時間 O(logn)**

これは注意不足ではない。Lesson 07 と `two-pointers-template.html` §4 の両方に
「各要素は最大2回、合計 2n で O(n)」と**明記してあり、それでも log n と書いた**。
読んで納得したものが上書きされている以上、**対立する模型が別にある**と見るべき。

推定される因果：**Lesson 07 が「捨てる」を核心概念として前面に出した**。
そして「捨てる」は二分探索の「半分捨てる → log n」と強く結びついている。
③で「捨てられる」と論証した直後に⑥を書いたため、③の語彙が⑥に漏れた。
つまり**レッスン側が作った誤概念**（[[0007-deriving-is-invalid]] と同じ、資料起因の失敗）。

**⑥ の他の欄は妥当**：[時間3] を `-` としたのは正解（167 に内側ループはなく、償却は不要）。
[時間2] は `-` ではなく `O(1)` と書くべきだが、実害はない。空間 O(1) は正しい。
**誤りは [時間1] のちょうど1点に絞れる。**

**③ の欠落: 3段目が書かれていない**

提出された③は「ソートされているため left+right で大きい小さいを判断でき、捨てることが可能」。
これは3段導出の**2段目（どちらを動かすか）**であって、3段目（捨てる側に良い答えが残っていない理由）ではない。
Lesson 07 のチェック3では正解している（「最大の相手と組んでも届かない」）。
**対話では言えるが、自分で書くと落ちる** ——[[0008-explanation-lags-implementation]] と同型の再発。

**Implications:**
- ③と⑥は**同じ「捨てる」の2つの側面**として一体で教える。
  ③＝なぜ捨ててよいか、⑥＝1回で何個捨てたか。**捨てる量が反復回数を決める**（1個→n回、半分→log n回）。
  分けて教えると今回のように混線するので、以後この2欄は必ずセットで扱う。
- 面接で言う版は**ギャップ論法**に統一する：`right - left` は毎反復ちょうど1減る。
  n-1 から 0 まで → 反復は高々 n-1 回。**償却を持ち出す必要がない**（Lesson 04 の3文は
  sliding window 専用、two pointers ではこちらが短くて確実）。テンプレート §4 を差し替えた。
- [[0010-bottleneck-not-transferring]] の一般則が再確認された：**手渡した一文は転移しない。**
  今回は「明記してある資料を持っているのに誤答」という、より強い証拠。
  対処は再説明ではなく、**誤概念そのものを名指しして対比させる**（two pointers vs binary search）。

**教える側への教訓（新規）:**
- **強調した語彙は、隣接する誤概念を引き寄せる。** 「捨てる」を核心に据えたことが log n を誘発した。
  キーワードを立てるときは、**その語が既に結びついている別の型を必ず並べて否定する**。
