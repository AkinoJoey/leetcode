# 与えた一文は、1往復後には転移しなかった（ボトルネック）

1004 を10分で自力完答。②⑥の rubric も、ボトルネックを除いて全項目正確。
`⚠` に挙げたのは `while 0 in counter and counter[0] > k` ——
これは実際にこのコードで唯一議論の余地がある行（`defaultdict` のキー生成を防ぐ防御的な書き方）で、
**自信のなさの照準が正確**。[[0008-explanation-lags-implementation]] の形式変更は完全に機能している。

**残った1点:**

直前のセッションで、ボトルネックの模範的な言語化を**明示的に手渡した**：

> 窓が1つずれても変わるのは端の1〜2個だけ。素朴解は**重なった部分を数え直している**。
> これは window 型すべてに共通する売り文句。

その次の問題（1004）でのボトルネック記述：

> 全ての部分配列を取り出すのが無駄

**転移しなかった。**「手法の名前を言い換えて無駄と呼ぶ」形に戻っている（424 の1回目と同型）。

**Implications:**
- **手渡した知識は、1往復では storage strength にならない**という直接の証拠。
  fluency（その場で読んで納得）と storage（次の問題で自分から出る）の乖離。
  [[0002-left-monotonicity]] の「読解では入らず実装で崩れる」と同じ構図が、説明の側でも起きている。
- 対処は説明の反復ではなく**検索練習**。次のパターン（two pointers）でも
  「この手法は何の再計算を避けているか」を毎回 rubric の枠として問う。
  枠にすれば埋まる（[[0009-rubric-fixed-explanation]]）ので、ボトルネック欄を
  **「何の再計算を避けたか」に文言変更**するのが最小コストの介入。
- 一般則として記録：**ボトルネックの言語化は、この学習者の一貫した最弱点**。
  ②③（素朴解→ボトルネック→最適化）の連鎖が面接での「なぜその解法か」に直結するため、
  優先度は下げない。ただし専用レッスンは割らず、毎回の枠で薄く反復する。

**別の観察（状態の選択）:**
- 1004 で `defaultdict(int)` を使ったが、必要なのは 0 の個数だけで `zero_count = 0` の int で足りる。
  424 からの**惰性**。動くので減点はしていないが、「状態は必要最小限」という観点は未獲得。
  次のレッスンで一行触れる。
