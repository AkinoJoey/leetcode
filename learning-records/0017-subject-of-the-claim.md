# ③が5回連続で②になる。原因は「主語」——消えた組が一度も名指しされていなかった

18. 4Sum の実装前パートで③を3往復。125（3往復）以来の停滞だが、**今回は原因が特定できた。**

## 症状：形式規則も定型文も通り抜ける

これまでに打った手はすべて効かなかった：

| 打った手 | 出典 | 結果 |
|---|---|---|
| ③の定型文（穴埋め） | [[0009-rubric-fixed-explanation]] | 前問の文面が流用されるだけ |
| 形式チェック「〜ない で終わる否定文」 | NOTES（167 後） | **通過した上で中身が空** |
| 弁別規則「〜する で終わったら②」 | [[0013-two-kinds-of-discard]] | 5回とも「捨てても問題ない」で閉じて回避 |
| 問題固有の量を個別に問う | [[0012-bound-not-value]] | 問1の時点で答えられず（後述） |

## 原因：③と②で**主語**が違うことを言っていなかった

5回の答案に共通していたのは、**消えた組が一度も名指しされていない**こと。

- **②の主語＝ポインタ。**「どちらを、なぜその向きに動かすか」
- **③の主語＝消えた組。**「移動の結果、視界から永久に消える組がどうなるか」

学習者は毎回「動かす方向が正しい理由」を書いていた。これは正しく、そして②。
定型文が `捨てる X は…` で始まるのに、**X が空欄のまま文だけ完成する**ので、
形式規則も定型文も通り抜ける。**規則は文の形を検査していて、主語を検査していなかった。**

## 決定的な観察：`d -= 1` で消える組を答えられない

個別質問（[[0012-bound-not-value]] で効いた手法）で聞いた：

> 「`d -= 1` を実行した瞬間、二度と評価されなくなる組をすべて挙げてください」
> → **回答「`nums[c]+nums[d]`」**（＝いま評価し終えた組）

正解は `(c+1,d) … (d-1,d)` の集合。
**評価済みの組と、未評価のまま失われる組の区別がついていない。**
これは 11 で記録した詰まり（[[0012-bound-not-value]] の詰まり3）と**完全に同一**。
あのときペア空間の絵で解いたが、**絵は 11 限りのものとして扱い、一般的な道具にしなかった**のが失敗。

同時に出た誤り：
- 問2の根拠が「`c,d` の添字は `b` より大きいため」＝**比較対象が違う**（`b` は無関係。正しくは `c' > c`）
- 問3「近くなった」＝**16 の語彙の持ち込み**。18 は closest ではなく厳密一致。
  「前問の文面を持ち込む癖」が **③・コード・docstring に続き、質問への回答でも**出た（4例目）

## 介入：ペア空間の格子を常設の道具にする（Lesson 12）

```
        d=3   d=4   d=5   d=6   d=7
 c=2     ·     ·     ·     ·     ✓ ← いまここ（和 > target）
 c=3           ·     ·     ·     ✗
 c=4                 ·     ·     ✗
 c=5                       ·     ✗
 c=6                             ✗
```

**`d -= 1` は「いちばん右の列」を消す。**`c += 1` は「行」を消す。
消えるのは常に**まだ見ていない側だけ**。この絵から③は4行で読める：

1. `✗` はどれも `✓` より下の行 ＝ `c` の添字が大きい
2. **ソート順より** `nums[c'] ≥ nums[c]`、`d` は共通 → `✗` の和は `✓` の和以上
3. `✓` の和は**すでに target を超えていた**
4. ゆえに `✗` のどれも target に**ならない**

**「和を小さくできる」が一度も出てこない。**出るのは〈消えた組〉〈順序の根拠〉〈超えていた事実〉の3つだけ。

## 手順化（`two-pointers-template.html` に追加）

③を書く前に、**先に2つ名指しする**：

1. **いま消えたのは、どの組か**（添字で、1組ではなく**集合**で。評価済みは含めない）
2. **その全部が、手元の値と比べてどうなるか**（根拠は**ソート順 / min / 添字**）

これが埋まれば③は「よって達し**ない**」で閉じるだけ。
**1 が書けないうちに③を書くと必ず②になる**——手元に移動の話しか材料が無いから。

## Implications

- **形式規則は文の形を検査するが、主語は検査しない。**
  [[0009-rubric-fixed-explanation]]（枠は埋まるが中身は保証しない）の最も深い形。
  枠・定型文・形式チェック・弁別規則と4段階の足場を積んだが、**主語がずれていると全部素通りする。**
  → 以後、新しい説明項目を導入するときは**最初に「この文の主語は何か」を言う。**
- [[0016-indentation-decides]] と同じ処方が効いた：**抽象的な基準は、目で見えるものに変換する。**
  「持ち越しか」→ インデント／「捨ててよい理由」→ **格子から消える列**。
  この workspace で2回連続で機能しており、**第一選択の介入**とみなしてよい。
- **11 で効いた道具を一般化しなかったのが直接の失敗。**ペア空間の絵は 11 固有の説明ではなく、
  two pointers 全体の③の読み取り装置だった。**一度効いた図は reference に格上げする。**
- 良かった点：③に「**ソート済の配列のため**」が初めて自発的に登場した
  （[[0015-preconditions-are-invisible]] の ⓪ が③に接続された）。
  ⓪前提そのものは 18 で**満点**——条件と、それを保証しているのが問題文かコードかまで言えた。
