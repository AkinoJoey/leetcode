# 125 完答。③には2種類あった／[時間2] の misfile に自己検算で決着

125 Valid Palindrome を完答。two pointers は 167・11・125 の3問通過。
コードは初回提出時点で正しく、修正はすべて docstring 側だった。

## ③に2種類あることが判明（教材の欠落）

`two-pointers-template.html` は125の③を「対称性より、外側の対は二度と関係しない」とだけ書いていた。
これは**結論であって型ではない**。実際に書かせると、167/11 で使った「上限を押さえる」型が
まったく適用できず、3往復を要した（毎回「両端を狭めて判定する」＝**手順**を書いてくる）。

整理すると③には2型ある：

| 型 | 問題 | 主張 |
|---|---|---|
| **優越型** | 167, 11 | 捨てた候補は**手元の値を超えられない**（上限を押さえる） |
| **縮小型** | 125 | 問題が**同じ形のまま小さくなる**（同値変形） |

125 は**探索ではなく検証**。②（どちらを動かすか）が存在せず必ず両方動くため、
③も「上限」ではなく「s 全体が回文 ⟺ 内側が回文」という同値主張になる。
教える側が「対称性から上限が出る」と誤って振ったのが3往復の一因。**謝罪して訂正済み。**

## 一貫した癖：結論だけ残して理由を落とす

③で3回連続、「二度と見る必要がない」（結論）は書けるのに、
「〜と同値になる」「〜に影響しない」（理由）が落ちる。
[[0012-bound-not-value]] の「手順を書いてしまう」と合わせて、**③の弁別規則**を渡した：

> ③の文は「〜する」で終わらない。「〜と同じ」「〜に影響しない」「〜ない」で終わる。
> 「〜する」で終わったら②（手順）。

## [時間2] の misfile が3回目 → 自己検算式で解決

167 で `right-left`、125 で `n回`。**どちらも「量」を「コスト」の欄に書いている。**
形式チェック（`O(…)` の形で終わること）を rubric に入れてあったが、それでも再発した。
そこで**自分で検出できる手続き**に変えた：

```
[時間1] × [時間2] + [時間3] を計算し、自分が書いた結論と一致するか見る
誤: n/2 × n回  + n = O(n²) ← 結論 O(n) と矛盾
正: n/2 × O(1) + n = O(n)  ← 一致
```

**警告でも形式規則でもなく、矛盾が自動的に露見する検算に落とした。**
NOTES の「警告は知識になるが習慣にならない／習慣にしたいものは提出物に埋め込む」の適用。
次問（15. 3Sum）で [時間2] が正しく入るかが、この介入の検証になる。

## 主張と実装の不一致（新しい観察）

②に「O(n) の追加メモリを避けた」と書きながら、実装に `s = s.lower()`（O(n) の新規文字列）が残っていた。
`[空間1]` に `l, r` しか書いていないのは、この行を見落としているため。
**②⑥で主張したことが実装と一致しているかの照合が抜けている。**
指摘後は `s[l].lower()` に修正し、主張と実装が揃った。
