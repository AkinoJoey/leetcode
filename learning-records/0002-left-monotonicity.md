# `left` の単調性は、読解では入らず実装で崩れる

Lesson 02 の演習1問目で手が止まった。書かれたコードは、外側ループの各反復で `left = 0` に戻していた
（＝ window ではなく総当たり O(n²)）。レッスン本文には「`left` は決して戻りません」と明示し、
償却解析の説明も読んでいたが、**実装時には再現されなかった**。

**Evidence:** 読解時点では理解しているように見えた（クイズは本文中にあり、単調性を問う設問は置いていなかった）。
実装で初めて崩れた。

**Implications:**
- 単調性は「知識」としては入ったが「技能」になっていない。次回、**コードを書かせる形**での retrieval が必要。
  選択式クイズでは検出できなかった。以後、window/two pointers 系は必ず穴埋めコードで確認する。
- 概念クイズが通っても実装が通るとは限らない、という一般則としても記録しておく。
  以降のレッスンは選択式だけで完結させない。

**教える側のミス（重要）:**
- 演習1問目に Best Time to Buy and Sell Stock を「助走」として置いたのは誤り。この問題は窓が invalid になる
  条件を持たないため、教えたテンプレート（`while is_invalid: 縮める`）が構造的に当てはまらない。
  型を教えた直後に、その型が当てはまらない問題を「同じ骨格」と称して出した。詰まって当然だった。
- 修正済み：1問目を Maximum Average Subarray I（固定長窓）に差し替え、
  「窓に見えて窓ではない例」として株の問題を反例に転用した。
- 一般則：**助走問題は、教えたテンプレートがそのまま動く問題でなければならない。** 反例を混ぜるのは
  型が定着した後（interleaving の段階）。

**言語仕様の事故（継続する傾向）:**
- `max_profit(max_profit, ...)` — `max` の誤記に加え、**戻り値を代入していない**。
- `range(len(prices), 0, -1)` — 初回で `IndexError`、かつ添字0に到達しない。
- [[0001-hashable-keys]] と同じ構図。詰まりの原因はアルゴリズムではなく Python 側、が2回連続。
  `./reference/` に Python の地雷を蓄積する方針は正しい。継続する。
