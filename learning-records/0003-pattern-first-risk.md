# パターン認識が先行し、素朴解の言語化が後退している

「最適解を勉強しすぎて brute force のほうが思いつきにくい」と本人が自己申告（2026-07-19）。
同じセッションで、Best Time to Buy and Sell Stock を window と誤認して手が止まる事象が起きている（[[0002-left-monotonicity]]）。
この2つは同じ現象の表と裏。

**Evidence:** パターンの当てはめは速い（Lesson 01 で Group Anagrams のキー設計に自力到達）。
一方、型が合わない問題に当たったとき、**型が合っていないと気づく手段を持っていない**。
素朴解を言語化していれば「区間の問題ではなく2点を選ぶ問題」と即座に判明したはずの場面だった。

**Implications:**
- パターン認識の速さ自体はミッションの目標そのもの（「5分以内にどのパターンか言語化」）。**抑制しない。**
  伸ばすべきは並行して働く検知器のほう。
- 素朴解は「アイデア」ではなく「問題文の直訳」であると再定義して伝えた。
  出てこない ＝ 創造性不足ではなく **問題文の精読を飛ばしているサイン**、対処は問題文に戻ること。
- 今後の演習指示には毎回②（素朴解を声に出す）を含める。ただし儀式化させないため
  「30秒で出なければ精度を落として進む」の上限も同時に伝えること。

**次に効きそうな介入:**
- **型が当てはまらない問題を意図的に混ぜる**（誤ったパターンを弾く練習）。ただし LR-0002 の教訓により、
  これは型が定着した後に限る。sliding window を2〜3問こなしてから。
- 「この問題に window は使えるか？ 使えないなら理由は？」という形式の判定クイズが有効そう。
  実装させるより速く、検知器だけを鍛えられる。

**教える側の所感:**
- 質問の質が上がっている（言語仕様 → 用語 → 面接戦略 → メタ認知）。
  自分の学習の歪みを自己申告できているのは、この短期間では良い兆候。
