新形式（実装前／実装後の自由記述、枠は採点側）での初回。

## 回収できたもの

- **空間 `O(n)` + 根拠「sort で利用するため」。**
  [[0014-inner-loop-multiplies]] で名指ししたまま**唯一未修正だった欄**を、2セッション越しに自力で回収。
  `l, r` しか見ずに `O(1)` と書く事故を回避できている。
- **前提に「length が 3 以上」。**私が想定していた答え（ソート順）ではないが、**これは本物の前提**。
  実際 `[1,2]` で例外を出さず `0` を返す（`best_sum = 0` が一度も更新されない）。
  しかも本人が挙げた `⚠` の行と同じ場所を指しており、接続が正しい。
- **`⚠` が7回連続で的中**（`if curr_diff < min_diff`）。

## 中心：⑥の根拠が3回連続で出てこない（15 → 16 docstring → 16 追い質問）

```
本人の答え: 「外側と内側で必ずループが回るため O(n²)」
追撃後   : 「外側のループの中で2つのポインタを基準に動かすから O(n²)」
```

**どちらも 424 に当てはまってしまう**（424 も外側ループの中で `left` を動かすが `O(n)`）。
結論は正しいが根拠が空。面接では必ず踏まれる場所。

### 原因は教材（3回目の同型）

`interview-protocol.html` の判定はこう書いてあった：

> 内側ループのポインタは、外側の次の反復に**持ち越されるか**？

これは正しいが、**頭の中で実行を追跡しないと判定できない**。
[[0015-preconditions-are-invisible]] の「前提はコードに書かれていないので見えない」と同型で、
**判定基準がコードの表面に現れていない**。

### 介入：意味判定を、構文の観察に置き換える

> **内側ポインタの初期化行が、外側ループの外にあれば足し算。中にあれば掛け算。**

```
424: left = 0          ← for の外  → n + n = O(n)
16 : j,k = i+1, n-1    ← for の中  → n × n = O(n²)
```

**インデントを見るだけで済む。**「外にある」＝「前の周の続きから始まる」＝「戻らない」＝
全体で n 回しか進めない＝足せる。「中にある」＝毎周ゼロから＝掛ける。

前提条件（内側ポインタが単調に進むこと）は残るが、これは [[0002-left-monotonicity]] で既習。
Lesson 11 のクイズで「この判定が壊れるのはどんなときか」として明示的に切り出した。

## `⚠` の中身：式は言えたが時制が抜けた

「`curr_diff` はどの3つ組の差か」→「`target` と `nums[i]+nums[j]+nums[k]` の差」。
式としては正しいが、**その行が実行される時点では `j` か `k` は既に動いている**という点が抜けた。
`curr_diff` / `three_sum` を移動前に確定させているので結果は正しいが、
危険なのは式ではなく**時制**。本人が `⚠` に挙げたのは正しい直感だった。
より安全な形（更新をポインタ移動の前に置く）を提示。

## 新形式（実装前／実装後・自由記述）の初回所見

- **項目の脱落は急増しなかった。**出たのは「時間の根拠」「`sort()` の時間計上」で、
  どちらも枠がある時代にも落ちていた項目。**枠の撤去による劣化は現時点で観測されない。**
- 一方、**空間は枠がないほうが良く書けた**（根拠つきで自発的に出た）。
  枠 `[空間1][空間2][空間3]` は3欄が互いに矛盾する事故を生んでいた（[[0014-inner-loop-multiplies]]）が、
  自由記述では一文で整合的に出る。**枠が誤りを作っていた可能性。**
- 問いの文言ミス：「**入力について**何を仮定していますか」と聞いたため、
  自分で `sort()` している以上ソートは「入力への仮定」ではない、という正しい解釈で答えが逸れた。
  → 以後「**この解法が成り立つために必要な条件と、それを保証しているのは誰か（問題文か、あなたのコードか）**」と聞く。

## Implications

- **抽象度が高い判定基準は、3回試して出なければ構文の観察に落とす。**
  「持ち越しか」（意味）→「初期化行のインデント」（構文）。
  NOTES の「警告は知識になるが習慣にならない」の解決形が一つ増えた：
  **チェックリスト化できないなら、目で見えるものに変換する。**
- 次の検証点：18. 4Sum で `[時間]` に**インデント判定で** `O(n³)` と言えるか。
  18 は内側2重なので、判定法をそのまま2回適用すればよい構造になっている。
