# ⑥で言った率が、コードの行に無かった（落ちないバグ）

704. Binary Search。⓪②③⑥はすべて正しく、**LeetCode も通った**。
にもかかわらず、提出コードは `l = mid+1` ではなく **`l += 1`**（`r` 側も `r -= 1`）で、
実測 O(n) の線形探索だった。⑥では「範囲は半分ずつ」と書いてある。
**主張と実装が正反対を向いているのに、テストが通るので誰も気づかない。**

## なぜ気づけなかったか

`l += 1` は**正しさを壊さない**。③（`nums[l..mid]` に target はない）が保証しているのは
「`l` を `mid+1` まで進めて**よい**」であって、進めなければならないとは言っていない。
だから答えは正しく返り、**遅いことだけが残る**。

これは [[0015-preconditions-are-invisible]]（16 の `sort()` 欠落）と同じ構造。
**落ちないバグは最後まで疑われない。** 16 は前提が、704 は率が、コードから抜けても動いた。

## 処方：⑥の量を、行で名指しする

⓪で確立した形（[[0015-preconditions-are-invisible]]：前提と、**それを保証している行の名指し**。
名指しできなければその行はまだ存在しない）を、そのまま⑥に適用する。

> **⑥で「毎回 X 捨てる」と言ったら、X を実現している行を指す。指せなければ、その行はまだ存在しない。**

介入後の再提出で「**`mid` を基準に `l` と `r` の距離を半分ずつにできる**」と書けた。
`mid` という語が入った時点で、主張がコードに接続されている。
**「抽象的な基準は、目で見えるものに変換する」の5勝目**
（インデント→⑥／格子→③／台帳→前処理／今回は更新行→率）。**第一選択の介入として確定。**

## 通過した項目

- **⓪ 満点**：条件＝ソート済み／保証は問題文。Lesson 10 の形が2回連続で出た。**獲得済み。**
- **② 通過**：ボトルネック文に素朴解の語（「舐める」）が入った。
  [[0019-the-range-not-the-array]] の形式チェックが2回連続で機能。
- **③ 2往復で通過**：区間の名指し → ソート順 → **否定文で結論**。
  1往復目は「小さいとわかる」で止まり、2往復目は「捨てても構わない」＝結論の言い換え。
  **[[0018-loop-start-not-constant]] の「結論の一文が落ちる」の再発**だが、
  「何を探しているか。その区間にあるか」の2問で出た。

## 新しい弱点：`⚠` が急所を外した（2回連続）

挙げたのは `while l <= r`。行としては妥当（閉区間の典型事故）だが、
**今回の急所は更新行**だった。18 で摩耗（直したばかりの行を挙げた）、704 で失中。
7回連続的中の時期は終わったとみなす。
→ 選定条件を「危なそうな行」から「**今日いちばん自信のない判断をした行**」に変更。
「壊れたことのない行」は日が空くと判定不能（[[0019-the-range-not-the-array]]）。

## storage strength：2セッション連続で retrieval が空

冒頭 retrieval（11 の③、07-22 に確立）は「忘れた」。前回も追い質問2つが空。
**手続きを渡せば潰せる型の失敗ではない。** 今回は再供給したうえで、
**次セッション冒頭で同じ問いを記述式で再テストする**（successive relearning）。
正直な「忘れた」は減点しない——取り繕われると decay が測れない。
