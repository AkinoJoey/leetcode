どこで切っても、片側は必ずソート済み

ここまでの3つの型は、すべて⓪に「ソート済み」と書けました。今日はソートされていない配列で、それでも半分捨てます。

まず思い出す（記述式・2問）

11. Container With Most Water。捨てる組について「面積は必ず今より小さい」と言い切るには、 〈高さの上限が上がらない〉のほかに、もう一つ要素が要る。漢字1文字で。

幅。③は2つの要素の掛け算で閉じる—— 高さは min に頭打ちされて上がらず、幅は必ず狭くなる。だから面積は必ず小さい。
07-29 の retrieval では高さ側だけが出て、幅が落ちていました （LR-0022）。 片方だけだと「同じ面積の組が残るのでは」に答えられません。

278 で教えた規則。更新に ±1 が付くかどうかを決めているのは、左右ではなく その枝で mid が ___ として生き残るか。空欄に入る漢字2文字。

候補。答えではないと確定したなら mid ± 1、 まだ答えかもしれないなら mid（±1 なし）。
「左は +1、右は無し」と位置で覚えると、型が変わった瞬間に崩れます。今日がその瞬間です。

[4,5,6,7,0,1,2]。ソートされていません。
⓪に「ソート済み」と書けない以上、ここまでの二分探索の根拠は全部使えません。
それでも O(log n) で探せます。前提を、成り立つ形まで弱めれば。

1. 壊れているのは全体だけ

回転ソート配列とは、ソート済み配列をどこか1か所で切って前後を入れ替えたもの。 大事なのは切れ目が1つしかないことです。

値4567012
mid = 3 で切ると、左 [4,5,6,7] はソート済み。切れ目は右側にある。

どこで切っても、切れ目は左右どちらか一方にしか入りません（切れ目は1つしかないので）。 切れ目が入らなかった側は、そのままソート済みです。これが今日の⓪です。

配列全体は単調でない。しかしどこを mid にしても、 [left, mid] と [mid, right] の少なくとも一方は必ずソート済みである。
保証しているのは問題文（「ソート済み配列を1回だけ回転したもの」）。

そしてどちらがソート済みかは、両端と mid を比べるだけで判定できます—— nums[left] <= nums[mid] なら左側。そうでなければ右側。値は全部見えているので、 呼び出しコストはありません（278 の ? の心配は無用です）。

[6,7,0,1,2,4,5]、left=0, right=6、mid=3（nums[mid]=1）。 ソート済みなのはどちら側か。漢字1文字で。

右。nums[0]=6 > nums[3]=1 なので、切れ目は左側（6 と 7 の後）にあります。 右側 [1,2,4,5] はソート済み。
「左がソート済み」が普通で「右」が例外、ではありません。どちらも同じ頻度で起きます。

2. ③が二段になる

ここが今日の本番です。ここまでの型では、③は 「消える区間を名指し → 理由 → 否定文で閉じる」の一段でした。 型Cでは、その前にもう一段入ります。

段1 — どちらがソート済みか

nums[left] <= nums[mid] か否かで決まる。target は一切登場しない。

段2 — ソート済みの側に target が入るか

その側の両端の値と比べるだけで、入るか入らないかを断定できる。

そして捨てられるのは——ソート済みで、かつ target が入らないと断定できた側です。

なぜ段1が要るのか

ソートされていない側では、両端の値と比べても何も断定できないからです。

添字0123456
値4567012
右側 [7,0,1,2] は両端が 7 と 2。target=5 は「7 と 2 の間」に見えるが、実際には無い。

右側の両端は 7 と 2。target = 5 は 2 と 7 の間にあります。 それでも右側に 5 はありません。ソートされていない区間では、両端は中身について何も語らない—— これは LR-0012（上限を押さえる）が使えなくなる条件でもあります。

一方、左側 [4,5,6,7] はソート済みなので、4 <= 5 < 7 から 5 はここにあると断定できる。だから右側を捨てる。断定できる側でしか、判断してはいけません。

同じ [4,5,6,7,0,1,2]、mid=3、今度は target = 1。 捨てられるのはどちら側か。漢字1文字で。

左。段1：ソート済みなのは左 [4,5,6,7]。 段2：1 < 4 なので、この範囲には入らないと断定できる。よって左側に答えはない。
捨てるのは常にソート済みの側とは限りません。判定するのがソート済みの側なだけで、 捨てるのはそこに無いと分かったとき。無いと分かればその側を、あると分かれば反対側を捨てます。

3. 最小値を探す（153）は、278 そのもの

33 の前に、もっと易しい型C——153. Find Minimum in Rotated Sorted Array を片付けます。 これは昨日の first_true がそのまま使えます。

最後の要素 last = nums[-1] を基準にして、述語 nums[i] <= last を並べてみます。

値4567012
≤ 2 ?✗✗✗✗✓✓✓
✗…✗ ✓…✓ と並び、一度 ✓ になったら ✗ に戻らない。最小値は最初の ✓。

配列自体は単調でないのに、この述語は単調です。 278 の⓪で書いたのはまさにこれ——必要なのはソート順ではなく単調性。 だから昨日の first_true をそのまま流用できます。 

def find_min(nums):
    lo, hi = 0, len(nums) - 1
    last = nums[-1]
    while lo < hi:
        mid = (lo + hi) // 2
        if nums[mid] <= last:
            hi = mid            # mid は「最初の ✓」かもしれない → 残す
        else:
            lo = mid + 1        # mid は ✗ と確定 → 消す
    return nums[lo]

±1 の付き方は 278 と1文字も変わっていません。今日の retrieval 2問目の規則 （mid が候補として生き残るか）が、配列が回転しても同じように効いています。
ランダムな回転配列 20 万件で min(nums) と完全一致することは確認済みです。

よく見る別バージョン

nums[mid] > nums[hi] とその時点の hi と比べる書き方も広く使われます。 やっていることは同じですが、比較相手が動くぶん不変条件の説明が一段難しくなります。 面接では last を固定して「述語が単調だから first_true」と言うほうが、 ③が短く済みます。

4. ⑥は今日も変わらない

毎回、残っている範囲の半分を捨てる（lo = mid + 1 / hi = mid がそれを実現している）。 log₂ n 回で O(log n)。空間は O(1)。

型Cで増えるのは1回あたりの判定の手数（段1 → 段2）だけで、回数は増えません。 定数倍の話なので O(log n) のまま——ここを混同して「二段だから log² n」と言わないこと。

今日の課題

33. Search in Rotated Sorted Array を、いつもの新形式で。

実装前（コードを書く前に、自由記述）：

  • ★ 探しているものを一文で（型B で新設した欄。型Cでは短くなるはずです）
  • ② 素朴解と、そのボトルネック（素朴解に出てくる語をそのまま含める）
  • ③ ——今日の本番。二段で書くこと

    • 段2：[4,5,6,7,0,1,2], target = 0, mid = 3 の場合について、 消える区間を先に名指ししてから理由。最後は否定文で閉じる

実装は、この骨組みの4つの空欄を埋める形で書いてください。

def search(nums, target):
    l, r = 0, len(nums) - 1
    while l <= r:
        mid = (l + r) // 2
        if nums[mid] == target:
            return mid

        if ______________:              # 段1：左がソート済みか
            if ______________:          # 段2：target は左に入るか
                r = mid - 1
            else:
                l = mid + 1
        else:                           # 右がソート済み
            if ______________:          # 段2：target は右に入るか
                l = mid + 1
            else:
                r = mid - 1
    return -1

空欄は不等号の向きと、等号を付けるかどうかが全てです。 nums[l] / nums[mid] / nums[r] と target しか使いません。
