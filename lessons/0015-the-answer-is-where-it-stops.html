1. 型Aが答えられない問い

35. Search Insert Position は 704 とほぼ同じ問題文で、最後の一行だけ違います。

問いtarget が無いとき
704（型A）target の添字は-1 を返す

型Aのコードを 35 に流用すると、while を抜けたところで return -1 に落ちます。 ここで手が止まる——というのが型Bを知らないときの典型です。 ところが、その時点で答えはもう left に入っています。

2. 不変条件を、そのまま答えにする

Lesson 14 §2 で置いた不変条件を思い出してください。 型Bでは、これをもっと強い形で持ちます。半開区間 [left, right) で：

left より左は全部 < target。right 以降は全部 >= target。
まだ調べていないのは [left, right) だけ。

ループが終わるのは left == right になったとき、つまり未調査の区間が空になったときです。 そのとき不変条件はこう読めます——その1点より左は全部 < target、その点以降は全部 >= target。 これは「境界」の定義そのもの。だから return left。 

def search_insert(nums, target):
    left, right = 0, len(nums)        # 半開区間 [left, right)
    while left < right:
        mid = (left + right) // 2
        if nums[mid] < target:
            left = mid + 1            # mid は条件を満たさない → 捨てる
        else:
            right = mid               # mid は「まだ候補」→ 残す
    return left
型Bの正体

これは bisect_left そのものです。標準ライブラリのドキュメントは、返り値 i について a[:i] は全部 < x、a[i:] は全部 >= x と保証しています—— 上の不変条件を、ライブラリの言葉で書いたもの。 面接で「bisect_left で1行ですが、手で書きますね」と言ってから書けると強い。

3. 決め事は三つとも変わる

Lesson 14 で「三つの決め事は連動する。一つ変えたら三つ見直す」と言いました。実演です。

型A（704）型B（35）
区間[left, right] 閉[left, right) 半開
right の初期値len(nums) - 1len(nums)
whileleft <= rightleft < right
更新（捨てる側）left = mid + 1left = mid + 1
更新（残す側）right = mid - 1right = mid
返すものreturn mid（見つけたら）return left（抜けたあと）

±1 が付くかどうかを決めているのは、mid がまだ答えの候補かどうかです。

  • nums[mid] < target のとき、mid は答えではありえない（自分より小さいので）。だから mid + 1。
  • nums[mid] >= target のとき、mid はまだ答えかもしれない。だから mid のまま。mid - 1 と書くと答えを飛び越します。

型Bで right = mid - 1 と書いてしまった。nums = [1,3,5], target = 3 のとき、 飛び越されてしまう添字は？（数字1つ）

1。left=0, right=3, mid=1、nums[1]=3 >= 3 なので残す側。 ここで right = 0 にすると、正解である添字 1 が範囲から消えます。 答えは 0 になり、間違い。「残す側」に -1 は付けない。

4. 終了性を、隣り合った2要素で確かめる

Lesson 14 で最も多いバグとして挙げたのが範囲が真に狭まらない無限ループでした。 型Bは right = mid と書くので、ここが一番怪しく見えます。手で確かめます。

left = 3, right = 4（未調査が1個だけ）のとき mid = (3+4)//2 = 3。

  • 捨てる側なら left = 4 → left == right で終了。
  • 残す側なら right = 3 → left == right で終了。

mid は必ず right より小さい（切り捨て除算なので）。 だから right = mid は必ず right を真に減らします。無限ループにはなりません。
——ただしこれは while left < right と組んだときの話です。 <= にすると left == right == mid で right = mid が何も変えず、止まらなくなります。 これが「三つの決め事は連動する」の意味です。

5. ⑥は型Aと同じ。ただし1行目から

毎回、残っている範囲の半分を捨てる（left = mid + 1 / right = mid がそれを実現している）。 n → n/2 → … → 1 で log₂ n 回。よって O(log n)。空間は反復なので O(1)。

括弧の中が今日の追加です。量を言ったら、その量を実現している行を名指しする （LR-0020）。 これは⓪で既にやっていること（前提と、それを保証している行）を⑥に移しただけです。
