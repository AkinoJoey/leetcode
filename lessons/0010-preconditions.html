1. 40分が溶けた本当の理由

コードのどこにもバグはありませんでした。にもかかわらず答えが合わない。 このとき人間が最後まで疑わないのが前提です。 アルゴリズムは目に見えるが、前提はコードに書かれていないので目に見えない。

そして 16 では、前提を落とすとプログラムが落ちません。 例外も無限ループも起きず、それっぽい数字を返してくる。だから「ロジックのどこかが微妙に違う」と読んでしまう。 探す場所が最初から間違っていたので、40分かけても見つかりません。

デバッグの順序

出力が合わないとき、ロジックより先に前提を疑う。
「この解法は、入力について何を仮定していた？ その仮定は今このコードで保証されている？」
前提の確認は10秒で終わります。ロジックの追跡は40分かかります。安いほうから。

2. 核心：③を一般形で書くと、前提が文に現れる

16 の③（捨ててよい理由）を、具体例ではなく一般形で書いてみます。 i は固定、探しているのは nums[j] + nums[k] が target - nums[i] に最も近いペア。 

いま three_sum < target だとする。j を固定したまま k を減らすと、
ソート順より nums[k'] ≤ nums[k] なので和はさらに小さくなり、
target からの距離はさらに広がる。
よって (j, k') の組はどれも、いま記録した値を超えられない。

2行目に 「ソート順より」 が出てきました。これは飾りではありません。 この一句が消えると③は成立しません。ソートされていなければ 「k を減らすと和が小さくなる」が言えず、 k の左側に target ぴったりの相手が残っている可能性を消せない。

③が依存している事実 ＝ その解法の前提。
③を書けば、前提は探すまでもなく文の中から出てくる。書かないと、コードからも消える。

LR-0012 で 「③が正しく書ければ、コードの分岐は自動的に決まる」と確認しました。今回はその続きです： ③が正しく書ければ、コードの前処理も自動的に決まる。

16 で nums.sort() が必要なのは、次のどの主張を成り立たせるためか。

ソートが与えているのは単調性——「ポインタを動かすと値が決まった向きに動く」という保証だけです。 これが③（＝捨てた組は手元の値を超えられない）を支えています。
なお「重複除去」は 15 で必要だった別の用途。16 は和を1つ返すだけなので重複スキップは要りません。 同じ sort() でも、問題ごとに理由が違う——15 の理由を 16 に持ち込まないこと。

3. 「11 ではソート要らないと言ったのに」の整理

LR-0012 で 「ソートは③の必須条件ではなく、上限を得る手段のひとつ」と強調しました。これは正しい。 ただしその逆——いつ要るのか——を並べて言っていませんでした。ここで揃えます。

問題③の上限はどこから来るかソート
11. Container With Most Water 幅は添字から、水位は min の性質から 不要
125. Valid Palindrome 上限ではなく対称性（同値変形） 不要
167 / 15 / 16 値の大小（和が単調に動くこと） 必須

判定は一つです。③が「値の大小」に依存しているならソートが要る。添字や対称性で済むなら要らない。

11 の h[j] は最後まで一度も要りませんでした。だからソートも要らなかった。 16 は nums[k] の値そのものを比べています。だから要る。 「11 で要らなかった」は 11 に固有の事情であって、two pointers 一般の性質ではありません。

③がどこに依存していたらソートが必要か。5文字で。

値の大小。③の文に「〜より大きい／小さい」が出てきたら、その順序は誰が保証しているのかを確認する。 誰も保証していなければ sort() を自分で書く。

4. ⓪前提 という欄を足します

interview-protocol の docstring に、②の前に一行足します。 

"""
⓪ 前提（この解法が入力に要求する条件）: 昇順にソート済みであること
   → コードで保証している行: nums.sort()

② 素朴解:  ...
"""

2行目が本体です。前提を書いたら、それを保証している行を名指しする。 名指しできなければ、その行はまだ存在していません——今回がまさにそれでした。

面接での効き目

⓪は減点回避ではなく加点です。「この解法はソート済みを前提にします。入力は保証されていますか？ されていなければ自分でソートしますが、その O(n log n) は全体の O(n²) に吸収されます」 ——これは①（問題の確認）と⑥（計算量）を一息で繋いだ発言で、面接官が最も聞きたい形です。

16 の nums.sort() は、⑥の計算量にどう計上するのが正しいか。

時間：n log n + n² = O(n²)。log は消えます。
空間：Python の list.sort() は Timsort で、最悪 O(n) の作業領域を使います。 ポインタしか持たなくても全体の空間は O(n)。 「O(1)」と書きたくなりますが、それは sort() を自分で書いたことを忘れている状態です （LR-0014 の「主張と実装の不一致」の再発地点）。
