探すものは、配列の中に無い

875 では piles をソートしても何も起きません。ソートしたい気持ちが空振りするのが、この型の入口です。

まず思い出す（記述式・2問）

11. Container With Most Water。低いほうの板を捨てる根拠は2つの要素で閉じています。 1つは「min(height[l], height[r]) × 幅 が上限であること」。もう1つは何か。 キーになる語を漢字1文字で。

幅（幅は減る一方）。上限だけでは捨てられません—— 「これから作れる組はすべて幅が今より小さく、水位は min のまま増えない」まで言って初めて閉じます。 ③は「上限」＋「その上限がこれ以上良くならない理由」の2要素で常に1組 （LR-0022）。 片方だけで止まる癖は 33 でも出ました（下限が落ちた）。今日も③でここを見ます。

33. Search in Rotated Sorted Array の else 枝（右半分 [mid, r] がソート済みの側）。 下限を与えるのは nums[mid]。上限を与えるのは何か。

nums[r]。だから右枝の条件は nums[mid] < target <= nums[r]。ここを nums[mid] > target > nums[r] と書くと nums[mid] > nums[r] を要求することになり恒偽——右半分を一度も見ません （LR-0024）。 上の1問目と同じ欠落の具体形です：根拠が2要素で閉じていない。

1. ソートしたい気持ちが、空振りする

875. Koko Eating Bananas — piles[i] 本のバナナの山が n 個。 ココは1時間に1つの山だけを選んで食べる。速さ k は1時間に食べられる上限の本数。 その山に k 本以上あれば k 本食べ、残りが k 本未満ならそれを食べきって、その1時間は終わり。 警備員が h 時間後に戻る。h 時間以内に全部食べ終えられる最小の k を返す。
問題文で唯一ひねってあるのは「余った時間を次の山に使えない」ところ

時間が余っても別の山には移れない。だから1つの山を食べきる時間は ceil(piles[i] / k)——山ごとに独立して切り上げになります。 合計を sum(piles) / k で見積もるとこの切り上げの分だけ短く出て、答えを間違えます。 

piles = [3, 6, 7, 11]、h = 8

k = 3  →  1 + 2 + 3 + 4 = 10 時間   ✗（8 を超える）
k = 4  →  1 + 2 + 2 + 3 =  8 時間   ✓   ← 答えは 4
k = 11 →  1 + 1 + 1 + 1 =  4 時間   ✓
k = 100 → 1 + 1 + 1 + 1 =  4 時間   ✓   ← 11 より速くしても縮まない

        k = 4 の内訳：山6 は 4本 → 残り2本 で2時間（余力2本は捨てる）

n（山の数）が、どんなに速くしても縮まない床です （h < n なら絶対に間に合わない）。 そして k = max(piles) でその床にもう到達している—— これが第3節の「hi = max(piles) で足りる」の中身です。

二分探索だと当たりをつけて piles.sort() と書いた瞬間に手が止まります。 ソートしても k は出てこない。答えの k は、そもそも piles の中に無いからです （piles = [3, 6, 7, 11], h = 8 の答えは 4——配列に無い数）。

単調性の保証者問題文あなた（証明が必要）
piles の順序—無関係。ソート不要

必要なのはソートではなく単調性だけ——これは 278. First Bad Version で確認済みです （Lesson 15）。 278 との違いは、単調な関数が問題文から与えられていないことだけ。自分で作ります。

2. 述語を作り、向きを確かめる

答えを二分探索するときの述語は、いつも同じ形をしています—— 「この候補で間に合うか」を Yes / No で返す関数。 

def ok(k):
    """速さ k で h 時間以内に食べ終わるか"""
    return sum(hours_for(p, k) for p in piles) <= h

そして⓪の仕事は、この ok が単調であることを言うことです。

k を大きくすると、どの山も必要時間が増えることはない（ceil(p/k) は k について非増加）。 合計時間も増えないので、一度 h 以内に収まったら、それより速い k でも必ず収まる。 よって ok は False … False, True … True の順に並ぶ。
「増える一方」ではなく「減らない」で足りる

hours(k) は k が増えても同じ値のままのことがよくあります （piles = [3] なら k = 3, 4, 5, … すべて1時間）。 単調性に必要なのは「厳密に減ること」ではなく「増えないこと」—— 真偽が ✗ ✗ ✓ ✓ ✓ と並び、一度 ✓ になったら ✗ に戻らない、これだけです。 「厳密に減らないから二分探索できない」と誤診しないこと。

3. 範囲の両端にも、根拠が要る

配列なら範囲は 0 … n-1 で悩みません。答えを探すときは範囲を自分で決める＝そこにも根拠が必要になります。

  • lo = 1：k = 0 は永久に食べ終わらないので定義域の外。1が最小の意味ある候補。
  • hi = max(piles)：1時間に1つの山しか食べられないので、 n 時間が最速。k を max(piles) より大きくしても合計は n のまま減りません。

上限を max(piles) ではなく「大きめに 10**9」としても動きます。 では hi の選び方に本当に必要な条件は何か。first_true が前提にしていることです。

ok(hi) が True であること。first_true は 「範囲内に必ず True がある」を前提に lo を返します。 True が1つも無ければ、無いことを検出せず hi をそのまま返す—— エラーにならないので気づけません（while lo < hi が偽になっただけ）。 max(piles) を選ぶ理由は「十分大きいから」ではなくok が True だと証明できるから。 ⓪で前提を名指しし、保証者を書く形（LR-0015）が、そのまま範囲の両端に適用されます。

4. コードは first_true そのまま

def minEatingSpeed(piles, h):
    def hours(k):
        return sum(-(-p // k) for p in piles)      # ceil(p / k)

    lo, hi = 1, max(piles)                          # ok(hi) は True（証明済み）
    while lo < hi:
        mid = (lo + hi) // 2
        if hours(mid) <= h:
            hi = mid                                # mid はまだ答えの候補 → 残す
        else:
            lo = mid + 1                            # mid では間に合わないと確定 → 消す
    return lo

③（消える区間とその根拠）は while の中の2行そのもので、 Lesson 15 の型Bと1文字も変わりません。 新しいのは hours と範囲だけ。型Dは新しい探索ではなく、新しい述語です。

ceil(p / k) を整数演算だけで書いてください（math も float も使わない）。

-(-p // k)（または (p + k - 1) // k）。 Python の // は負の側へ切り捨てるので、符号を反転すれば切り上げになります。 math.ceil(p / k) は float を経由するため、値が大きいと丸め誤差で1ずれることがあります （p は 10**9 まで。面接では「整数のまま扱いました」と一言添えると強い）。

5. ⑥は、log の中身が変わる

この解法の時間計算量。n = len(piles)、m = max(piles)。

O(n log m)。二分探索しているのは 1 … m なので回数は log m。 その毎回 hours(mid) が全山を舐めるので O(n)。掛けて O(n log m)、空間は O(1)。 log の中身は二分探索した対象の大きさ——配列長ではありません。

毎回、残っている k の候補の半分を捨てる（hi = mid / lo = mid + 1）。 候補は m 個なので log₂ m 回。1回ごとに hours が O(n)。 よって O(n log m)、空間は反復なので O(1)。

言った量を実現している行を名指しする形（LR-0020）は今日も同じです。 ただし名指しする行が2種類になりました——率を作る行（hi = mid / lo = mid + 1）と、 1回のコストを作る行（hours の sum）。 log の外に何が掛かっているかは、この2つ目を名指しできたときだけ言えます。

面接での言い方——m は入力サイズではない

log m の m は値であって要素数ではありません。厳密には入力の ビット数に比例する量なので、「値の範囲に対して log」と言い分けられると理解が伝わります。 実務上は m ≤ 10**9 なら log₂ m ≈ 30——ほぼ定数なので、 「実質 O(30n) です」と添えるところまで言えると強い。
