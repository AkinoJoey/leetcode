一点だけ：状態は必要最小限に

1004 で知りたいのは0 の個数だけです。defaultdict ではなく zero_count = 0 という int 一つで足ります。424 からの惰性ですね。
減点はしません（動くので）。ただし面接では状態が小さいほど説明が短くなり、バグも減ります。 「窓の中で本当に知りたいのは何か」を、状態を選ぶ前に一言で言う癖をつけてください。

今日の型：両端から挟み撃つ

left, right = 0, len(arr) - 1

while left < right:
    if 条件を満たす:  return ...
    elif 小さすぎる:  left += 1     # 大きくしたい
    else:             right -= 1    # 小さくしたい

計算量はそのまま3文テンプレートが使えます。 left は増えるだけ、right は減るだけ。各要素は最大2回。合計 2n で O(n)。 Lesson 04 で作った道具が、パターンをまたいで再利用できます。

難所は「動かし方」ではない

骨格は一目で分かるはずです。この型で面接官が踏み込むのは、別の場所です。

left += 1 をした瞬間、あなたは arr[left] を永久に捨てています。 二度と見に戻りません。ではなぜ、そこに正解がないと言い切れるのか。

導出の3段

  1. いま持っている値を書く（和、面積など）
  2. どちらを動かせば目的の方向に動くかを、ソート順から言う
  3. 捨てる側に、より良い答えが残っていない理由を一文で言う

167. Two Sum II で実演

arr = [2, 7, 11, 15]、target = 18。left=0, right=3 から始めます。

1. 最初の arr[left] + arr[right] は？

2 + 15 = 17。target の 18 より小さいので、和を大きくしたい。

2. 和を大きくするには、left と right のどちらを動かすか？

left。ソート済みなので left を右に動かすと値が増えます。 right を動かすと減ってしまう。②はソート順から機械的に決まります。

3. ここが本番。arr[left]=2 を捨てても大丈夫だと言うには、2 がどの相手と組んだ結果を見れば十分か？（数字で）

15（＝残っている中で最大の相手）。
2 にとっていちばん有利な相手と組んでも和は17で、まだ18に届かない。 他の相手はもっと小さいのだから、2 は誰と組んでも絶対に届かない。だから捨ててよい。
これが③です。「最も有利な条件で試してもダメだったから、残りは見なくてよい」—— この論法は two pointers の全問題で同じ形をしています。

面接での言い方

「left はいま最大の相手と組んでも target に届きません。 他のどの相手ともっと組んでも和は小さくなるだけなので、left は解に含まれ得ません。 よって安全に捨てられます。」
