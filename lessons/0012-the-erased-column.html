③は、消えた列の話

5回続けて②を書いています。原因が分かりました——③が何について語る文なのかが、ずれています。

あなたが毎回書いているもの

「ソート済の配列のため、sum > target の場合、配列内の最大の値である nums[d] の インデックスを -1 することで、和を小さくすることが可能。そのため捨てても問題ない」

この文が語っているのはポインタの移動です。「どちらを、なぜその向きに動かすか」。 それは正しく、そして②です。

③が語るのは移動ではありません。移動した結果、視界から永久に消える組がどうなるかです。
主語が違います。②の主語はポインタ、③の主語は消えた組。

5回の答案すべてに共通していたのは、消えた組が一度も名指しされていないことでした。 だから定型文（捨てる X は…）も形式規則（「〜ない」で終わる）も通り抜けてしまう。 X が空欄のまま文だけ完成するからです。

消えるものを、絵にする

18. 4Sum で a, b を固定したとします。残った添字が 2〜7、 そこから (c, d) のペアを選ぶ。候補はこの格子の全マスです。

d=3d=4d=5d=6d=7
c=2····✓
c=3···x
c=4··x
c=5·x
c=6x

✓ がいま評価した (2, 7)。和は target を超えていたとします。 ここで d -= 1 を実行すると——いちばん右の列がまるごと消えます。

消えるのは (3,7) (4,7) (5,7) (6,7)。4組です。 (2,7) ではありません——それはもう見た。③が守るのは、この4組の分です。

③が主張しているのは、この4組についてだけ

· のマスは捨てていません。d が 6 に来れば、まだ全部届きます。
③は「解が存在しない」という強い主張ではなく、「消えた分には無い」という弱い主張 （LR-0012）。 弱いからこそ、たった一文で証明できます。

絵から③を読む（4行）

  1. ✗ はどれも ✓ より下の行 ＝ c の添字が大きい
  2. ソート順より nums[c'] ≥ nums[c]。d は共通。 よって ✗ の和は、どれも ✓ の和以上
  3. ✓ の和はすでに target を超えていた
  4. ゆえに ✗ のどれも target にならない

4行目が③です。「和を小さくできる」は一度も出てきません。 出てくるのは、消えた組・ソート順・そして超えていたという事実の3つだけ。

手順にします

③を書くときは、いきなり文を書かない。先に2つ、名指しする。

  1. いま消えたのは、どの組か（添字で。1組ではなく集合で）
  2. その全部が、手元の値と比べてどうなるか（根拠はソート順 or min or 添字）

この2つが埋まれば、③は「よって、それらは【目標】に達しない」で閉じるだけです。 1が書けないうちに③を書こうとすると、必ず②になります——書ける材料が移動の話しか無いからです。

ドリル：消えた組を名指しする

③は聞きません。消える組だけ答えてください。

上と同じ格子で、いま (2,3) を見ていて和が小さすぎたので c += 1 した。 消える組をすべて（例: (2,4)(2,5) のように）

(2,4) (2,5) (2,6) (2,7) ＝ c=2 の行まるごと。 d を動かしたときは列が、c を動かしたときは行が消えます。 そして消えるのは常にまだ見ていない側だけ。

167. Two Sum II で arr = [1,3,5,7,9,11]、left=0, right=5 を見て和が大きすぎた。 right -= 1 で消える組は何組か（数字だけ）

4組。(1,5) (2,5) (3,5) (4,5)。(0,5) は評価済みなので含みません。 arr[5]=11 を右端に持つ組は、これで全滅します。

③の文の主語として正しいのはどちらか。

消えた、まだ見ていない組。「評価を終えた組」は捨てていません（もう答えに反映済み）。 「残っている組」はこれから見るので③の対象外。 ③が守る範囲は、たったいま失った分だけです。

18 の③（あなたが書くもの）

上の手順で、a, b 固定・sum > target の場合の③を一文で書いてください。 材料はすべて出揃っています。「小さくできる」が入っていたら②です。

書けたら、そのまま実装へ。a, b の2重ループ・c, d の両端・重複スキップ、 そして計算量は Lesson 11 の判定法を2回適用します。
