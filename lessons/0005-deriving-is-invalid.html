Lesson 05 · 可変長ウィンドウ

is_invalid を自分で導く

テンプレートが隠していた、唯一の難所。

先に謝ります。テンプレートが悪い

私が渡した可変長ウィンドウのテンプレートは、こう書いてありました。 

while is_invalid(state):
    remove(state, s[left])
    left += 1

is_invalid は関数名であって、答えではありません。 そして 424 において、難しいのはそこだけです。 私は問題の唯一の難所を、それらしい名前で包んで隠していました。解けなくて当然です。

なぜこれまで露呈しなかったか。3（Longest Substring）では is_invalid が 問題文にほぼ直書きされていたからです。「重複がある」→ char in seen。翻訳がいらない。
424 は初めて導出が必要になった問題です。階段が一段上がっています。

あなたが書けていたもの

これは重要なので先に確認します。以下は全部正しい。

  • for right, char in enumerate(s) — 骨格
  • while ... : left += 1 — 縮める構造
  • right - left + 1 — 境界（今回も正確）
  • defaultdict(int) — 状態の選択

構造は全部書けていて、条件式だけが書けなかった。 詰まりが1点に絞れているのは良い状態です。今日はその1点だけをやります。

手順：日本語 → 量 → 不等号

is_invalid は、ひらめきで出すものではありません。3段階の翻訳で出します。

① 問題文から「valid とは何か」を日本語一文で書く

この窓は、k 回以下の置き換えで、全部同じ文字にできる

これは問題文の直訳です。考えていません。写しているだけです。

② その一文を、窓の中で数えられる量に翻訳する

「全部同じ文字にする」なら、どの文字に揃えるのが得か。 当然、いま窓の中にいちばん多くある文字です。それ以外を全部置き換えることになる。

置き換えが必要な個数 ＝ 窓の長さ − 窓の中で最も多い文字の個数

③ 不等号にする

valid   ⟺  (right - left + 1) - max_freq <= k
invalid ⟺  (right - left + 1) - max_freq >  k

これで is_invalid が埋まりました。ひらめきは一度も使っていません。

数える

s = "AABABBA"、k = 1。窓が "AABAB"（添字0〜4）のときを考えます。

1. この窓の長さは？

5。right - left + 1 = 4 - 0 + 1 = 5。

2. 窓 "AABAB" の中で、最も多い文字の個数（max_freq）は？

3。A が3個、B が2個。多いほうの A に揃えるのが得です。

3. 置き換えが必要な個数は？

2。5 - 3 = 2。B を2個とも A に変える必要があります。

4. k = 1 のとき、この窓は valid か invalid か？（どちらかを英語で）

invalid。2回の置き換えが必要なのに、許されるのは1回まで。 5 - 3 = 2 > 1。だから while が回って窓を縮めます。

5. while の条件（invalid の式）を書いてください

(right - left + 1) - max_freq > k。 あなたが書いた counter[char] > k は、単に「今の文字が k 個より多い」という意味で、 問題文のどの文とも対応していません。①の日本語を経由しなかったために出た式です。

穴埋め

class Solution:
    def characterReplacement(self, s: str, k: int) -> int:
        counter = defaultdict(int)
        left = 0
        max_len = 0

        for right, char in enumerate(s):
            # 1) 入れる
            counter[char] += 1

            # 2) invalid な間、縮める
            while (right - left + 1) - max(counter.values()) > k:
                counter[____A____] -= 1
                left += 1

            # 3) ここで窓は必ず valid
            max_len = max(max_len, right - left + 1)

        return max_len

空欄 A（窓から出ていく文字を減らす）

s[left]。あなたは counter[left] と書きました。
left は添字（数）、counter のキーは文字です。 counter[left] は「整数 0 という名前の文字」を数えることになり、エラーも出ずに静かに壊れます。 添字と値の取り違え。これは新しい種類の事故なので記録しておいてください。

順序が重要

あなたのコードは counter[char] += 1 が while の後にありました。 それだと、今の文字を入れていない状態で invalid 判定することになります。
テンプレートの順は ①入れる → ②縮める → ③更新。この順序に意味があります —— ③に到達した時点で窓が valid であることを保証するためです（不変条件）。

計算量（3文テンプレートの再演）

前回の3文をここでも使います。ただし一箇所だけ追加が要ります。

6. max(counter.values()) は毎回いくつの値を走査するか？（大文字英字のみの制約下で）

最大26。定数です。だから全体は O(26n) = O(n)。 面接では「文字種は26で定数なので、計算量には効きません」と一言添えます。 ここを黙って O(n) と言うと突っ込まれます。

発展（今は不要）

max_freq を変数で持ち、減らさないという有名な高速化があります。 面接で聞かれたら「答えは縮まないので max_freq を減らす必要がない」と説明できますが、 今日は上の素直な版で構いません。説明できない最適化を書くほうが危険です。

今日の課題

  1. 424 を白紙から書く。ただしコードより先に、①の日本語一文を書いてから始めること。 # valid とは: ___ というコメントを、必ず最初の行に置いてください。
  2. 1004. Max Consecutive Ones III を解く。 同じ導出をもう一度やる問題です。①の日本語一文が出せれば勝ちで、あとは同じ骨格が動きます。

提出時のコメントは ⚠ いちばん自信のない行 を忘れずに（「なし」は禁止）。
