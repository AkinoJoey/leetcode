Lesson 03 · 境界

境界は推論しない、数える

アルゴリズムは合っているのに通らない。犯人はいつも同じ場所にいる。

今日の1つの狙い

前回、Maximum Average Subarray I が自力で解けませんでした。 ここで確認しておきたいのは、詰まった場所がアルゴリズムではなかったということです。

前回のセッションの記録を見ると、あなたは「窓を右に1つずらすとき、出ていく1個を引いて入ってくる1個を足す」という 考え方には自力で到達しています。つまり解法は分かっていた。 にもかかわらず通らなかった。1セッションで3回、同じ種類の事故が起きています。

  • range(len(prices), 0, -1) — 初回で IndexError、しかも添字 0 に届かない
  • right - left + 1 の +1 が要る理由を説明できない
  • range(k+1) で初期窓を k+1 個ぶん合計してしまう（同一セッション内で2回）

3つともオフバイワンです。1個ずれ。
今日のレッスンは新しいパターンを増やしません。この1点だけを潰します。

用語

オフバイワン（off-by-one）：範囲や個数の指定が、正解より1だけ多い／少ない誤り。 「0 から数えるか 1 から数えるか」「終端を含むか含まないか」が食い違うときに起きる。 用語集に追加済み。

原因：あなたは境界を「推論」している

前回のあなたの発話には、こういう形が繰り返し出てきました。

「range は終端を含まないから、たぶん +1 が要るはず」

これは推論です。前提（range は終端を含まない）は正しい。 でも、そこから「だから +1」までの一歩は、頭の中で暗算しています。 そして人間の暗算は、境界に関しては驚くほど当たりません。あなただけの話ではなく、 プロのエンジニアが最も多く出すバグの種類がこれです。

対処は、推論をやめることです。代わりに機械的な手続きに置き換えます。

道具：3秒でできる代入検算

境界に迷った瞬間に、必ずこれをやります。例外なく、毎回です。

  1. いちばん小さい具体値を置く。nums = [1, 2, 3]、k = 2 くらい。
  2. 答えを手で書き出す。「窓は [1,2] と [2,3] の2つ」
  3. 自分のコードにその値を入れて、一致するか見る。

重要なのは順番です。先に手で答えを出してから、コードを見る。 コードを先に見ると、脳はそれを正当化する方向に働きます。

なぜ小さい値なのか

nums が10要素だと、頭の中で数えるコストが高すぎて検算そのものが失敗します。 3要素なら指で数えられる。検算は、暗算しなくて済むサイズでやる。

ドリル：数えるだけ

ここからは書いて答えてください。推論せず、まず紙かエディタに具体値を書き出してから入力すること。 即答できたとしても、書き出す手順を踏んでください。今日鍛えたいのは答えではなく手続きです。

1. nums = [1, 2, 3]、k = 2。長さ2の連続部分列はいくつあるか？

[1,2] と [2,3] の2つ。一般に長さ n の配列に長さ k の窓は n - k + 1 個。 3 - 2 + 1 = 2。この式も暗記ではなく、いま数えた結果と一致することを確認してください。

2. 添字 left = 3 から right = 7 まで（両端を含む）。要素はいくつあるか？

3, 4, 5, 6, 7 の5個。right - left + 1 = 7 - 3 + 1 = 5。 +1 が要るのは、両端の両方を含むから。引き算だけだと「間の隙間の数」になり、端が1つ落ちます。

3. range(3) が生成する値をすべて書くと、いくつの値になるか？

0, 1, 2 の3個。range(n) は 0 から始まり n を含まないので、ちょうど n 個。 ここが前回 range(k+1) で k+1 個を足してしまった事故の発生源です。

4. nums の先頭から k 個ぶんの合計を for i in range(?) で取りたい。? に入るのは？

range(k)。k 個ほしいなら range(k)。 設問3で確認したとおり range(k) はちょうど k 個です。k+1 にすると1個多い。 「k 個ほしい → range(k)」を、考えずに出せる形にしておくこと。

5. nums の長さが6、k = 3。窓の左端が取りうる値はいくつあるか？

左端は 0, 1, 2, 3 の4通り（左端が3のとき窓は添字3,4,5 でちょうど末尾）。 6 - 3 + 1 = 4。設問1と同じ式です。窓の個数 = 左端の候補数だから当然一致します。

6. 長さ k の窓の右端が right のとき、左端の添字を right と k で表すと？

right - k + 1。設問2の「個数 = right - left + 1」を left について解いた形です。 検算：right = 4, k = 2 なら左端は 3。窓は添字3,4 で2個。合っています。

穴埋め：Maximum Average Subarray I

道具を持った状態で、前回できなかった問題に戻ります。アルゴリズムはもう埋めてあります。 空欄はすべて境界です。今日鍛えたところだけを問うています。 

class Solution:
    def findMaxAverage(self, nums: List[int], k: int) -> float:
        # 1) 最初の窓（先頭 k 個）を合計する
        window_sum = 0
        for i in range(____A____):
            window_sum += nums[i]

        best = window_sum

        # 2) 窓を1つずつ右にずらす。right は「新しく入ってくる要素」の添字
        for right in range(____B____, len(nums)):
            window_sum += nums[right]           # 入ってくる1個
            window_sum -= nums[____C____]       # 出ていく1個
            best = max(best, window_sum)

        return best / k

空欄 A

k。ドリル4と同じです。k 個ほしいなら range(k)。

空欄 B（right の開始値）

k。最初の窓は添字 0〜k-1 を使い切っています。 次に新しく入ってくるのは添字 k。検算：k=2 なら初期窓は 0,1、次は 2。合っています。

空欄 C（出ていく要素の添字）

right - k。ここが今日いちばん間違えやすい箇所です。
ドリル6で「窓の左端は right - k + 1」を出しました。左端は窓の中に残る要素。 出ていくのはその1つ手前、つまり right - k です。
検算：k=2, right=2 のとき、新しい窓は添字 1,2。出ていくのは添字 0。2 - 2 = 0。合っています。
ここで right - k + 1 と書くのが典型的なオフバイワンで、まだ窓に残っている要素を引いてしまいます。

前回の詰まりの正体

nums[left] と書いてしまった、という記録が残っています。 left を「窓の左端」として管理していると、引くべきなのは left ではなく left の1つ前という ねじれが起きます。上のコードのように right だけで書くと変数が1本減り、ずれる余地も減ります。 固定長の窓は、変数を right 1本にする。これは覚える価値のある型です。

今日の Python の地雷

range(a, b, -1) は a から始まり b を含まずに減る。 range(len(nums), 0, -1) は len(nums) から始まるので初回で IndexError、 さらに 0 を含まないので先頭要素に到達しません。逆順は range(len(nums) - 1, -1, -1)。 ここも代入検算：len=3 なら 2, 1, 0。正しい。 境界の検算チェックリストに対応表を置きました。
