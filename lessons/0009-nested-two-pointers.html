Lesson 09 · Two Pointers

内側ループは、部分問題

15 は新しい型ではない。167 を n 回解くだけ。そう見ると、バグも計算量も同時に決まる。

まず、あなたの骨格は正しい

sort() → i を固定 → j, k で挟む。これは 3Sum の標準解そのものです。 パターンの選択で迷った形跡はありません。今日直すのは2箇所だけで、 その2箇所は同じ一つの見落としから出ています。

1. コードは通っていません

手元で走らせた結果です。

nums = [-3,-1,0,1,2,3]
あなたの出力: [(-3,0,3), (-1,0,1)]
正しい答え  : [(-3,0,3), (-1,0,1), (-3,1,2)]

(-3,1,2) が落ちています。原因は break です。
i=0（-3）のとき、j,k は (-1,3) → (0,3) で和 0 を見つけ、 そこで break して i=1 に進んでしまう。-3 を含む残りのペアを探していません。

なぜ break と書きたくなったか

167 の記憶です。167 は「答えはちょうど1つ、見つけたら return」でした。 15 は全部列挙する問題です。
内側ループの止め方は、外側の問題文が決めます。「1つ返せ」なら止めてよい。「全部返せ」なら その i に対する解を出し切るまで止めない。

正しくは、和が 0 のときも探索を続ける——両方のポインタを動かします。

if three_sum == 0:
    ans.add((nums[i], nums[j], nums[k]))
    j += 1
    k -= 1        # ← break ではなく、次のペアへ

2. 計算量は O(n) ではなく O(n²)

提出された⑥はこうでした。

[時間1] n回   [時間2] O(1)   [時間3] O(n)
→ 時間: O(n)

前回渡した自己検算式（[時間1] × [時間2] + [時間3]）に入れると n × O(1) + O(n) = O(n)——矛盾が出ません。 つまりあなたは検算を正しく実行しても、この誤りを見つけられなかった。 これは検算式のほうが不完全でした（私の資料の欠陥です）。直します。

足し算になる条件

[時間3] を足す（＝償却）ことが許されるのは、 内側ループのポインタが外側の反復をまたいで生き残るときだけです。

毎回リセットされる		 掛け算　n × n = O(n²)
判定は一つ：内側のポインタは、外側の次の反復に持ち越されるか？
持ち越される → 足し算（償却）／初期化される → 掛け算。

だから [時間3] の欄には、これからどちらなのかを明記してください。 数字だけ書くと、この区別が消えます。 

[時間3] 内側ループ: 各 i で最大 n 回。j,k は毎回リセットされるので掛け算
→ 時間: n × O(1) + n × n = O(n²)

ついでに：ソートを計上する

nums.sort() は O(n log n)。今回は O(n²) に飲まれるので結論は変わりませんが、 自分で書いたソートは必ず⑥に一行出すこと。O(n) や O(n log n) の解では、ここが支配項になります。

3. 空間の欄が自己矛盾している

[空間2] 入りうる最大の要素数は: O(1)
[空間3] 入力サイズに依存するか: する
→ 空間: O(1)          ← [空間3] が「する」なら O(1) にはならない

[空間2] と [空間3] は同じことを二度聞いています。 「最大要素数が定数」なら依存しない、「依存する」なら定数ではない。 片方だけ埋めて片方を流用すると、ここでねじれます。2つの答えが整合しているか、書いた直後に見てください。

正しくは：ans に入る三つ組の数は入力に依存する（→ 出力ぶん）。 加えて Python の sort() は O(n) の作業領域を使います。 面接での言い方は「出力を除けば O(n)（ソートの作業領域）」が安全です。

手を動かす

1. nums=[-2,0,1,1,2]。break 版が取りこぼす三つ組を書いてください。（例：(-1,0,1)）

(-2,1,1)。i=0 で先に (-2,0,2) を見つけて break するため、 -2 に対する2組目に到達しません。取りこぼしは常に「同じ i の2組目以降」に出ます。
※ (-3,1,2) と入力した方へ：それは本文の例（[-3,-1,0,1,2,3]）の答えです。考え方は同じ。

2. n=6、break なし。i=0..5 の内側 while は合計何回まで回りますか？（i ごとの上限は n-1-i 回）

15回（5+4+3+2+1+0）。n(n-1)/2 です。 sliding window ならここは合計 6 回でした。この差が、足し算と掛け算の差。

3. 上を踏まえて、15 の時間計算量を O(…) の形で書いてください。

O(n²)。ソートの O(n log n) はこれに飲まれます。 面接では「ソートに n log n、その後 i ごとに O(n) の two pointers を n 回で n²。支配項は n²」と言えば完成です。

4. 内側ループを「償却して足し算」にできない理由を、j, k の挙動として一語で。（例：単調に増える）

リセットされる（＝毎回初期化される／外側に持ち越されない）。 償却論法は「各要素が全体を通じて高々◯回しか触られない」と主張する型です。 j,k がリセットされると同じ要素が何度でも触られるので、この主張が成立しません。

③について（今回は減点なし、でも一段足りない）

提出された③：

和が0よりも大きい、あるいは小さいとわかっているため捨てても問題ない

「〜ない」で終わる否定文になっており、形式は合格です。ただし3段目が結論だけ。 15 の③は 167 とまったく同じ構造なので、そのまま書けます（i を固定すれば -nums[i] を探す 167 です）：

和が target より小さいとき、nums[j] は残りで最大の相手 nums[k] と組んでも届かない。 他の相手は nums[k] より小さいので、nums[j] は誰と組んでも届かない。 よって nums[j] は（この i のもとで）解に含まれ得ない。

「この i のもとで」が入るのが 15 の特徴です。③も部分問題の中の主張になります。

今日の課題

  1. 15 を直して通す。break を修正し、⑥の [時間3] は 「リセットされるので掛け算」を明記した形で書き直す。[空間2] と [空間3] の整合も確認。
    余力があれば set をやめて重複スキップで書いてください（面接ではこちらが標準）： 
    for i in range(len(nums)):
    if i > 0 and nums[i] == nums[i-1]:
        continue                       # 同じ i を二度やらない
    j, k = i + 1, len(nums) - 1
    while j < k:                       # ← 探索の継続条件。ここに重複判定を足さない
        ...
        else:
            ans.append([nums[i], nums[j], nums[k]])
            j += 1
            k -= 1
            while j < k and nums[j] == nums[j-1]:
                j += 1                 # ← 重複スキップ。0 を見つけた直後の、この位置だけ

    while j < k が2つ出てきますが、役割はまったく別です。 外側＝探索を続けるか、内側＝いま見た値と同じものを飛ばすか。 2つを and でつなぐと、「重複しているときだけ探索する」という別物になります。

    ⚠ にはこの while の境界を書いてください——実際ここが唯一の危険地帯です。
  2. 16. 3Sum Closest。 同じ帰着（i を固定 → two pointers）ですが、目的が「ちょうど 0」から「最も近い」に変わります。
    実装前に一つだけ答えてください：和が target と一致したとき、そこで return してよいか？ 今日の「内側ループの止め方は外側の問題文が決める」で判断できます。
