Lesson 02 · 所要 15分

窓を伸ばして、縮める

「連続」の二文字が見えたら、この型を疑う。

前回、内側ループが探索なら辞書で潰せるという型を手に入れました。 今日はその型が効かない場所を一つ確定させます。

辞書は「どこにあるか」を答えますが、順序を捨てます。 だから問題文に「連続する部分文字列」「連続する部分配列」と書かれた瞬間、辞書だけでは足りません。 連続を保ったまま O(n) に落とす型が sliding window です。

先に思い出す

本文を読む前に、前回の一問。外して構いません。

Group Anagrams のキーに、sorted(word) ではなく文字数のカウントを使う利点は？（語長 k）

ソートは1語あたり O(k log k)、カウントは O(k)。全体では O(nk log k) → O(nk)。 面接では両方を挙げてから選ぶのが強い——「ソートキーが素直ですが、 カウントキーなら log が落ちます。語が長いならこちらです」。あなたが自力で到達したのは後者です。

知識：窓には二つの動きしかない

sliding window は、配列の上に区間 [left, right] を置き、右端を1つずつ進めるだけの走査です。 やることは二つだけ。

  1. 伸ばす：right を進めて、新しい要素を窓の状態に足す。
  2. 縮める：条件が破れたら、破れなくなるまで left を進めて要素を捨てる。

「重複のない最長の部分文字列」を例にすると、そのまま以下になります。

def length_of_longest_substring(s):
    window = set()          # 窓の中にある文字
    left = 0
    best = 0

    for right, ch in enumerate(s):
        while ch in window:            # 条件が破れている間だけ縮める
            window.remove(s[left])
            left += 1
        window.add(ch)                 # ここで初めて安全に入れられる
        best = max(best, right - left + 1)

    return best
口に出すべき一文

「while を抜けた時点で、窓は必ず条件を満たしています」——これが不変条件です。 だから毎ステップ max を取ってよい。面接では、コードより先にこの一文を言うと、 以降の説明が全部この上に乗ります。

なぜ二重ループなのに O(n) なのか

面接で必ず聞かれます。答えは償却解析です。

left は決して戻りません。各要素は高々1回窓に入り、高々1回出ていく。 だから内側の while は、全体を通して合計 n 回しか回りません。

「見た目は O(n²) ですが、left が単調に増えるので全体で O(n) です」。この言い方を覚えてください。

どこで使えないか

窓は縮めたら戻れません。つまり捨てた要素は二度と拾わない。 これが成り立つのは、窓を縮めると条件が改善する方向に単調なときだけです。 負の数を含む配列で「和が k 以上の最短区間」は、縮めると和が増えることがあるので window では解けません。

型の使い分けと、状態の持ち方の一覧は Sliding Window テンプレート にまとめました。

技能：思い出す

問題文のどの言葉が、sliding window を最も強く示唆するか？

決定打は「連続」。飛び飛びで選んでよいなら窓は使えません（→ DP や backtracking）。 ソート済み配列のペアは two pointers、存在判定だけなら 前回のハッシュです。

「最長」を求める型で、best を更新すべき位置はどこか？

窓が valid であることが保証されているのは while を抜けた後だけ。 なお「最短」を求める型では逆で、valid な間に縮めながら更新します。向きが反転する点に注意。

窓の長さを表す式として正しいのは？

[left, right] は両端を含む閉区間なので +1。 left == right のとき長さ1になるか、で毎回確かめられます。off-by-one はこの型の最頻出バグです。

実践：今日やること

各問 20〜30分で詰まったら解答へ。上のコードを見ずに書くこと。

  2. Longest Substring Without Repeating Characters（Medium）— 本命。 書き始める前に「窓の状態として何を持つか」を一文で言うこと。
  3. Longest Repeating Character Replacement（Medium・余力があれば）— 状態が set では足りなくなる問題。Counter が要ります。
窓に見えて窓ではない例

Best Time to Buy and Sell Stock は window の問題として紹介されがちですが、厳密には違います。窓が invalid になる条件が存在しないため、 縮めるべき瞬間が来ない＝while に書くことが無い。正しい型は「これまでの最小値を持って1回走査する」です。 left が単調に前進するという発想だけが共通しています。 テンプレートが当てはまらないと感じたら、それは型の選択が違うという正しい信号です。
